# Security reporting

This policy covers SAAA source code and bundled application behavior. No supported-version matrix, private reporting contact, response deadline, or security support commitment has been established yet.

Do not publish credentials, personal recordings, conversation data, or exploit details in a public issue. A private reporting route and responsible maintainer still need to be designated before this policy can provide a complete vulnerability reporting process. This document does not claim that such a route is available.

For current storage and diagnostics behavior, see [README](README.md#local-data-and-privacy). Public contributions should follow [CONTRIBUTING](CONTRIBUTING.md).

## Information for a future private report

Prepare the affected commit and platform, affected feature, minimal reproduction, expected impact, and any workaround. Use synthetic data and placeholder credentials. Keep exploit details private while the reporting route is unresolved; a normal public issue is not a substitute.

## 日本語

対象はSAAAのソースコードと同梱アプリの動作です。現在、非公開の報告窓口・担当者・対応期限・サポート対象バージョンは確定していません。公開Issueに脆弱性の詳細や認証情報、録音、会話データを書かないでください。

報告に備える場合は、対象commit、OS、影響する機能、架空データでの再現手順、影響範囲、回避策を整理してください。窓口が確定した際に、この文書を更新します。
