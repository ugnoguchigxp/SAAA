# コンセプトと現行実装のレビュー（2026-09-27）

## 判定

現行の通常会話経路は five-provider concept/runtime contract を完全には満たしていない。
単体の部品が存在することと、実際の会話経路に接続されていることは別である。
本レビューでは通常会話の入口から保存・再生までを追い、設定、話者検証、LARM、Web、
Memory/World、永続キュー、キャンセル、監査、画面遷移との接続を確認した。
全ファイルの行単位監査、実機の会話受け入れ試験は完了していない。

## 未解決のコンセプト差分

1. ASR途中結果は表示されるが、1.5秒単位の改訂をQwenへ渡す経路がない。確定入力のみが依頼になる。
2. 現行会話のTTSには、ユーザー割り込みで再生位置を保持してpause/resumeする接続がない。
   AEC・ducking・ASR継続は、この機能の代わりにはならない。
3. 回答本文の先行読み上げは行わず、保存完了した回答を再生する。句点ごとの先行再生を戻すには、
   途中本文の永続化、世代、取消し、最終本文との一致を同時に保証する必要がある。
4. 通常会話は複数役割のLARMセッションを共有する。役割ごとの準備状態の独立性は未達。
5. 前の依頼のcancel/replaceはあるが、複数依頼を識別する質問ID・回答先ID付きのwaiting_user契約は未実装。
6. Ornithに提供されるWeb・メモリーツールだけで、コンセプト全体の操作・長期仕事を実行できるとは確認できない。
7. 削除済みの旧会話Runtimeを参照するテストが残っており、全体テストが成功しない。
   成功扱いにするためのテスト削除・無条件skipは行っていない。
