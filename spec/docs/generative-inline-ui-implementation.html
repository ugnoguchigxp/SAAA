会話内UIの実装結果

2026-09-12。初期導入範囲の実装を追加した。機能は既定OFFの試用版として提供する。実モデルの生成成功率とTauri上の詳細な性能測定は完了しておらず、一般公開の合格判定には含めない。

コードレビューと修正結果（2026-09-12）に、追加で修正した不具合と最新の検証結果を記録した。

使い方

  1. 会話画面上部の「会話内の道具（試用）」を有効にする。
  2. ツール呼び出しに対応したOpenAI互換接続、またはAgentSession WebSocket接続で「この会話の実行状況をダッシュボードで見せて」と依頼する。
  3. 「一覧を右へ、件数を左へ」などの変更を会話で依頼する。編集は新しい版として表示され、過去の画面は変わらない。
  4. 名前を入力して「画面を保存」、または会話で保存を依頼する。「保存した画面」から検索して再表示できる。
  5. 「この時点の情報を残す」で取得値を固定する。「保存一覧から除く」は過去の会話参照を残したまま一覧から除く。

今回確認した選択中のAgentSession SSE接続は、turn APIにUIツール定義を渡せない。SAAA側のUI生成ツールはこの接続方式では動作しない。画面に接続条件を表示し、既存のルート設定は変更していない。

実装した範囲

  • text／ui Content Part、旧履歴との互換、UI生成後の会話更新通知、要約によるテキスト投影。UI定義を通常のテキスト差分やTTSへ流さない。
  • present_ui、get_ui、save_ui、search_ui、open_ui。会話・実行スコープ検査、同一run／callの重複排除、最大3画面／turn、生成失敗2回で修正終了。
  • SQLiteのView・追記型Revision・Instance・Snapshot・外部操作状態。編集と公開の競合検査、明示保存、日本語部分一致検索、再利用、アーカイブ、未保存の孤立View回収。
  • Stack、Grid、Cell、Text、Metric、Table、Chart、Status、Actions、ModelStatus。12列配置と狭幅での縦配置、表の絞り込み・並べ替え・ページ送り。
  • 許可済みデータ取得、15秒の共有取得、画面外と非表示ウィンドウでの新規取得停止、取得失敗表示、再表示時の状態復元。
  • 同じ会話の実行停止。実行状態と有効なキャンセルハンドルを確認し、要求IDによる重複排除と監査記録を行う。Snapshotから操作できない。
  • 履歴の前後cursor取得、初回30件・保持上限150件、メッセージ仮想化、フォーカス中の行の保持、高さ測定。従来のlist_messages APIも維持する。

OpenUIの採否と計画からの変更

OpenUI 0.2.15で独自部品libraryの試作・解析テストを行ったが、本番bundle生成が約4GBのメモリ上限で停止する事象を3回再現した。計画の撤退条件に従い、本番描画はSAAAの限定JSON定義とSemanticRendererへ切り替えた。同じ部品・状態管理・取得境界を使う。OpenUIは試作の開発依存に限定し、本番のimport経路には含めない。

代替方式のVite buildは約1秒で完了した。InlineUiの遅延ロード部分は約12KB、gzipで約4KB。メインbundleには500KB超過の警告がある。数値はこの開発機でのbuild記録であり、ユーザー操作時間やRSS測定の代わりにはしない。

  • 版1の定義は検証済みJSON文字列で保存する。試作の限定OpenUI記法も読めるが、モデルにはJSONを要求する。未知版は要約と再試行へ戻す。
  • 初期版はUIひとつを独立したassistantメッセージとして原子的に保存する。文章と複数UIを一つのDB行へ混在させる方式にはしていない。
  • SnapshotはInstance内の上限1MiBのJSONにまとめる。初期sourceはDBからの会話別集計に限るため、共有取得キーは会話IDとsource IDとする。
  • 新しい前後取得APIを別moduleへ追加した。既存の片方向cursor APIの契約を変更しない。
  • 別Composer、Patch言語、途中UIストリーム、Native Featureへの昇格は計画どおり初期導入の対象外。
