Context

SituationのShadow policyは、提案を控える弱い根拠として入力活動の有無を必要とする。 一方、正確なidle時間、最終入力時刻、key、button、cursor位置は行動履歴になり得るため、 application層、永続層、診断、UIへ渡してはならない。

Decision

  • macOSではCGEventSourceSecondsSinceLastEventTypeとkCGAnyInputEventTypeだけを使用し、event tapを作らない。
  • 取得した秒数は同じRust call stack内でactive | recent | idle | unknownへ変換し、raw値をreturnしない。
  • 外部contractはcategoryとready | disabled | unsupported | degradedのhealthだけとする。
  • monitoring無効時はOS APIを呼ばず、unknown + disabledを返す。
  • Input Activityはscene、confidence、evidence、userAttentionを変更しない。idle + readyのときだけShadowのSUGGESTをOBSERVEへ抑制する。
  • permission拒否を推測しない。非finite、負値、overflowはunknown + degraded、非macOSはunknown + unsupportedとする。

Privacy boundary

保存または表示してよい値はcategory、health、bounded reason code input-idleだけである。

exact idle seconds/milliseconds、last input timestamp、raw CGEvent、keyboard/mouse/tabletの内訳、 cursor位置をSQLite、diagnostics、console、Tauri event、React stateへ追加しない。

Consequences

  • Input Activityから人物の在席、離席、安全な割り込み可否を推定できない。
  • OS APIの挙動が将来変わった場合も、bounded fallbackで既存policyへ戻せる。
  • 予期しないAccessibility/Input Monitoring promptが出た場合はshippingを止め、adapterを再評価する。
  • development buildと署名済みpackaged buildで予期しないpermission promptが出ないことを 実機確認し、release evidenceへ記録した後にStatusをAcceptedへ変更する。
