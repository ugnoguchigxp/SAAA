ContextStill MCP 型別Memory Tool改修依頼書

0. 依頼情報

  • Status: Implementation Request
  • Requested: 2026-08-29
  • Requester: SAAA MVP 3 Memory Architecture
  • Target repository: ContextStill
  • Verified ContextStill baseline: b20d78e
  • Primary target: TypeScript MCP server and shared retrieval services

本依頼は、ContextStill MCPのMemory FetchをExperience、Rule、Skillの型別Toolへ整理し、 SAAAのSessionless Agentが必要なMemoryだけを安全に選択取得できるようにするものである。 ContextStillの保存schema、既存Episode・Knowledge lifecycle、primary coding workflowを置き換える依頼ではない。

SAAA側の上位契約は MVP 3 Memory Architecture実装契約のSection 14を参照する。

1. 依頼する変更

ContextStill MCPに次の三つのmodel-visible Fetch Toolを追加する。

recall_experience → EpisodeCard
recall_rule       → Knowledge type = rule
recall_skill      → Knowledge type = procedure

各Toolは同じ検索結果を名前だけ変えて返すaliasではない。入力schema、返却型、Context上の意味、 output budget、no-hit契約を型ごとに固定する。ただし検索・ranking・repositoryは既存serviceを再利用し、 新しいMemory storeまたは重複indexを作らない。

既存search_episodes、fetch_episode、 search_knowledgeは互換呼び出し可能に残す。 新typed toolsの安定後、default exposed catalogではtyped toolsを優先し、generic toolsは compatibility callableへ段階的に移す。

3. 現状の問題

  1. search_knowledgeはRuleとProcedureを同時に返せるため、Agentが判断基準を探しているのか、 実行手順を探しているのかがTool選択時に固定されない。
  2. Episode、Rule、ProcedureはContext上のtrustと利用方法が異なるが、共通のtyped envelopeがない。
  3. 現行search_episodes outputにはrepository path/keyやraw locatorを含み得る。 SAAAは抽象化済みopaque source ref以外を受け取ってはならない。
  4. 現行no-hitはToolによってplain textのno contentになり、callerが型付きで処理できない。
  5. context_compileはcoding task用に複数Memoryを編集するため、SAAAのMemory種別別Fetchには広すぎる。
  6. legacy search_memoryはsession filterとRaw memoryを扱うため、Sessionless SAAAの Experience Fetchに使用すると責務が混線する。

4. 固定する責務境界

Table: Memory types and authority
Memory 正本 Tool Context上の扱い
Raw Conversation SAAA SQLite recall_conversation historical raw evidence
Experience ContextStill EpisodeCard recall_experience past precedent evidence
Rule ContextStill Knowledge type rule recall_rule constraint candidate
Skill ContextStill Knowledge type procedure recall_skill procedure candidate
User Core / Working / Capsule SAAA SQLite なし SAAA Context Builderによる自動投影
  • ContextStillはSAAAのRaw Conversationを検索しない。
  • 三つのtyped toolsはすべてread-onlyで、Memoryを登録、昇格、更新しない。
  • active Memoryだけを通常返し、draftまたはdeprecatedをcaller inputで有効化させない。
  • 返却MemoryはAgent PolicyまたはCurrent User instructionを上書きする権限を持たない。
  • scopeは既存のrepoとglobalだけを使用し、新scopeを追加しない。

5. 共通MCP Contract

5.1 Common input

{
  "query": "string, 1..2000 chars",
  "projectRef": "optional opaque string",
  "includeGlobal": true,
  "domains": ["optional"],
  "technologies": ["optional"],
  "changeTypes": ["optional"],
  "limit": 5
}
  • 全input schemaをadditionalProperties: falseにする。
  • limitはdefault 5、minimum 1、maximum 10とする。
  • projectRefはopaque、case-sensitive、最大256文字とする。
  • 新typed toolsはrepoPath、repoKey、sessionIdを受けない。
  • queryをdiagnostic logまたはusage receiptへ平文保存しない。

5.2 Common output envelope

{
  "contractVersion": "memory-recall-v1",
  "memoryType": "experience | rule | skill",
  "trust": {
    "trustClass": "untrusted_memory_evidence",
    "instructionAuthority": "none"
  },
  "retrieval": {
    "mode": "lexical-metadata-v1",
    "degradedReasons": []
  },
  "items": [],
  "noContent": true,
  "truncated": false
}
  • no-hitでも同じJSON envelopeを返し、items: []、noContent: trueとする。
  • Tool response全体は4,000 token以内をhard capとする。
  • 各itemの本文は1,200文字以内を初期capとし、超過時は型を壊さずfield単位で短縮する。
  • outputにrepoPath、repoKey、raw locator、DB id以外の内部識別子を出さない。
  • score、confidenceは0〜100へ正規化し、scaleをTool間で揃える。
  • degraded時も別形式へfallbackせず、degradedReasonsへbounded reason codeを入れる。

6. recall_experience

再利用可能な成功、失敗、mixed、unknown Episodeを取得する。

6.1 Input extension

{
  "query": "similar failure with a reusable avoidance",
  "outcomeKinds": ["success", "failure", "mixed"],
  "projectRef": "opaque-or-omitted",
  "includeGlobal": true,
  "limit": 5
}

outcomeKindsはsuccess、failure、 mixed、unknownだけを許可する。

6.2 Item output

{
  "id": "episode-id",
  "title": "abstracted title",
  "situation": "abstracted situation",
  "action": "abstracted action",
  "outcome": "abstracted outcome",
  "lesson": "abstracted reusable lesson",
  "outcomeKind": "failure",
  "confidence": 88,
  "score": 92,
  "sourceRefs": [
    {
      "kind": "opaque",
      "ref": "saaa://memory-source/opaque-id"
    }
  ]
}
  • Episode以外を返さない。
  • actionを含む。現行compact mapperで欠落している場合はtyped projectionで補う。
  • source refはallowlist済みopaque schemeだけを返す。
  • Raw Conversation本文、raw query hint、filesystem locatorを返さない。

7. recall_rule

現在の判断へ適用候補となる宣言的RuleとGuardrailを取得する。

7.1 Input extension

{
  "query": "rule for preserving raw-memory provenance",
  "polarities": ["positive", "negative", "neutral"],
  "intentTags": ["guardrail"],
  "projectRef": "opaque-or-omitted",
  "includeGlobal": true,
  "limit": 5
}

7.2 Item output

{
  "id": "knowledge-id",
  "title": "rule title",
  "rule": "declarative rule body",
  "polarity": "negative",
  "appliesTo": {},
  "intentTags": ["guardrail"],
  "confidence": 91,
  "importance": 85,
  "score": 93,
  "originRefs": []
}
  • searchKnowledgeCandidatesをtypes: [rule]で強制する。
  • statusはactiveに固定し、draft/deprecatedを返さない。
  • RuleはPolicyではなくconstraint candidateである。
  • Rule本文中の命令形をsystem instruction roleへ変換しない。

8. recall_skill

再利用可能な実行手順をProcedureから取得し、構造化Skillとして返す。

8.1 Input extension

{
  "query": "procedure for revising a memory tool contract",
  "intentTags": ["workflow"],
  "projectRef": "opaque-or-omitted",
  "includeGlobal": true,
  "limit": 5
}

8.2 Item output

{
  "id": "knowledge-id",
  "title": "skill title",
  "useWhen": "applicability condition",
  "workflow": ["step 1", "step 2"],
  "verification": ["check 1"],
  "avoid": ["unsafe shortcut"],
  "appliesTo": {},
  "confidence": 90,
  "importance": 82,
  "score": 94,
  "originRefs": []
}
  • searchKnowledgeCandidatesをtypes: [procedure]で強制する。
  • 既存のUse when、Workflow、Verification、 Avoid section contractからtyped projectionを作る。
  • sectionを安全にparseできないactive Procedureはuntyped bodyとして返さず、除外して malformed_skill_projectionをdegraded reasonへ追加する。
  • workflowの各stepは順序を保持し、VerificationとAvoidをWorkflowへ混ぜない。
  • Skillは実行候補であり、現在のUser instructionなしに自動実行する権限を持たない。

9. Agent Tool選択契約

Table: Tool selection examples
User intent 選ぶTool 選ばないTool
以前何を話したか SAAA recall_conversation ContextStill全Tool
似た成功・失敗事例 recall_experience recall_rule、recall_skill
守るべき原則・禁止事項 recall_rule recall_experience、recall_skill
再利用できる進め方 recall_skill recall_experience、recall_rule
  • no-hitを理由に残り二Toolを無条件に全件呼び出さない。
  • 一つのintentが複数型を明示的に必要とする場合だけ、必要な型を順番に追加取得する。
  • context_compileはcoding taskのprimary workflowとして維持し、 typed toolsを毎task三件すべて呼ぶworkflowへ変更しない。

現行MCP_V2を直接破壊しない。新catalogは明示feature gate MCP_TYPED_MEMORY_TOOLSで段階導入する。

12. Work Package

CTM-00 — Contract fixture

  • 三Toolのinput/output JSON fixture、no-hit、degraded、invalid inputを先に固定する。
  • type purity、active-only、trust metadata、source-ref allowlistをfixture化する。
  • SAAA側fixtureとmemory-recall-v1 contractVersionを共有する。

Gate: ContextStillとSAAAが同じfixtureをparseできること。

CTM-01 — Typed projection services

  • Experience、Rule、Skillのpure projection serviceを実装する。
  • Skill section parser、source-ref sanitizer、output budgetを実装する。
  • repository path、raw locator、metadataのallowlist外fieldを除外する。

Gate: 誤種別0、raw identifier残留0、malformed Skillのfail-closed成功。

CTM-02 — MCP Tool registration

  • 三Toolをtyped-memory.tool.tsへ登録する。
  • MCP_TYPED_MEMORY_TOOLSによるexposed/callable catalogを実装する。
  • Tool descriptions、initial instructions、public MCP docsを更新する。

Gate: catalog snapshotとschema compatibility testが成功すること。

CTM-03 — Backend parity

  • PostgresとSQLiteで同一fixture、同一type、同一no-hit responseを確認する。
  • score scale、active status、scope selection、source refsのparityを確認する。
  • embedding unavailable時のlexical fallbackとdegraded reasonを確認する。

Gate: backend別contract差分0件。

CTM-04 — SAAA isolated integration

  • isolated ContextStill DBとSAAA fixture profileだけでfeature gateをONにする。
  • Conversation / Experience / Rule / SkillのTool selection fixtureを実行する。
  • Context Healthがtrust、type、budgetを維持することをend-to-endで確認する。

Gate: Section 14のAcceptance Criteriaを満たすこと。

CTM-05 — Closeout

  • compatibility期間、default catalog、rollback結果をrelease evidenceへ記録する。
  • generic toolsを非公開化するかはusage telemetryとclient確認後に決める。
  • known limitationsとmalformed Skill件数を記録する。

13. PrivacyとSecurity

  • query、Episode本文、Rule本文、Skill本文をlogまたはerror messageへ保存しない。
  • Tool outputをusage receiptへ複製しない。
  • source refはsaaa://memory-source/等の承認済みopaque schemeだけを返す。
  • project/client/person name、absolute path、internal endpoint、credentialを返さない。
  • retrieved textをtrusted system instructionへ昇格しない。
  • draft、deprecated、malformed、source policy違反itemはfail-closedで除外する。
  • ContextStillからSAAA SQLiteへ直接接続しない。

16. Stop conditionとRollback

次のいずれかが発生した場合、feature gateをdefault ONにしない。

  • 三Toolのいずれかが別Memory typeを返す。
  • draft、deprecated、malformed itemが通常resultへ入る。
  • raw locator、repo path、client/project/person identifierがtyped outputへ入る。
  • no-hitまたはdegraded時だけoutput schemaが変わる。
  • typed toolsのために新しいMemory table、重複index、DB migrationが必要になる。
  • 既存context_compile workflowまたはgeneric callable contractが壊れる。
  • ContextStillがSAAA SQLiteへ接続する必要が生じる。
  • Tool resultにinstruction authorityを与えないとAgentが動作しない。

Rollbackは次の順で行う。

  1. MCP_TYPED_MEMORY_TOOLSをOFFにする。
  2. 現行v2 exposed catalogへ戻す。
  3. typed toolsはcallable compatibilityとして残すか、未公開のまま停止する。
  4. repository、Episode、Knowledge schemaは変更していないためdata rollbackは行わない。

18. 完了状態

SAAA asks what happened
  → recall_conversation in SAAA SQLite

SAAA asks what worked or failed
  → recall_experience in ContextStill
  → typed Episode evidence

SAAA asks which constraint applies
  → recall_rule in ContextStill
  → typed Rule candidate

SAAA asks how to perform the work
  → recall_skill in ContextStill
  → typed Procedure candidate

All ContextStill results
  → active only
  → bounded
  → opaque provenance only
  → untrusted_memory_evidence
  → instructionAuthority = none

完了後、AgentはMemoryの種類をTool選択時点で明示できる。ContextStillは既存のEpisode・Knowledge repositoryとrankingを再利用しながら、SAAAへは型が純粋で、boundedで、source policyを満たす結果だけを返す。 これにより、Memory Fetchを増やしてもContext Windowの健全性と現在指示の優先順位を維持できる。
