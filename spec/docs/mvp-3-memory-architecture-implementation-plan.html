MVP 3 実装契約 — Sessionless Continuity, Context Health, and Selective Memory

0. 文書の役割

  • Status: Revised implementation plan
  • Revised: 2026-08-29
  • SAAA baseline: ae9b84a + working tree
  • Shipping client: macOS版SAAA desktop
  • 対象: SAAA、ContextStill、QA、運用

本文書は、User-facing Sessionの廃止、Context Windowの健全性維持、待機時のMemory整理、 ContextStillへの再利用可能なEpisode・Rule・Skill保存を実装するための契約である。 特に、すでに実装済みのrecall_conversationをSQLite会話探索の唯一の責務として扱い、 同じRaw会話を別table、別FTS、別toolへ複製しない。

完了の定義はM3-00〜M3-12を順に完了し、Section 18の Acceptance Criteriaをisolated fixtureと実機canaryの両方で満たすことである。

1. 結論と固定判断

SAAA
├─ User-facing Sessionless normal Chat
├─ Raw conversation source of truth
│  └─ conversations + conversation_messages
├─ SQLite conversation exploration
│  └─ recall_conversation only
├─ User Core / Working State / Continuity Capsule
├─ Per-turn Context Projection + Context Health
├─ Idle job coordination
├─ Reflection source windows
└─ Pre-egress abstraction + source-reference resolution

ContextStill
├─ EpisodeCard: success / failure / mixed / unknown
├─ Rule
├─ Procedure = Skill
├─ Typed MCP Recall
│  ├─ recall_experience
│  ├─ recall_rule
│  └─ recall_skill
├─ Deduplication / consolidation / lifecycle
├─ Rule / Skill induction
└─ Source-backed Episode + Knowledge retrieval
  1. 通常ChatのUser-facing Sessionを廃止する。「新しい会話」「Sessionを開く」「Sessionを再開する」 操作を通常Chatから除き、app再起動、日付変更、Provider変更、話題変更で関係性をresetしない。
  2. conversation_idは物理的な保存、実行、provenanceのために内部へ残せる。 ただし、Userに選ばせず、Memory partition、Recall検索範囲、人格の境界として使用しない。
  3. Sessionlessを実現するためにRaw履歴を新しいTimeline tableへcopyしない。 conversation_messagesをRawの正本として維持する。
  4. SQLiteから過去会話をたどる処理はmemory::recallへ集約する。 model-visibleな会話探索toolはrecall_conversation一件だけとする。
  5. 再利用MemoryのFetchは、Experience、Rule、SkillでContext上の意味と出力schemaが異なるため、 ContextStill MCPのrecall_experience、recall_rule、 recall_skillへ分離する。三件ともConversation Toolではない。
  6. Sessionlessは全履歴の常時投入を意味しない。Providerへ送るContextは毎Turn再構築し、 input budget、output reserve、重複、矛盾、鮮度、provenance、instruction priorityを検査する。
  7. ContextStillはPersonal Memory DBにしない。保存対象は、抽象化後も将来再利用できる経験、 成功、失敗、Rule、Procedure = Skillだけとする。
  8. ContextStillのscopeは既存のrepositoryとglobalだけを使う。 特定プロジェクトの現在状態、人物、予定、会話全文は保存しない。

3. 今回達成すること

  1. 通常ChatをUser視点で一つの継続関係にし、Session操作を0件にする。
  2. Raw履歴の正本と既存Recallの検索能力を維持し、二重保存と二重検索を避ける。
  3. Current instructionを一回だけ含むContextEnvelopeを毎Turn生成する。
  4. Output reserveを先に確保し、Context HealthがREDの入力をProviderへ送信しない。
  5. Continuity CapsuleをRaw sourceとcheckpointから再構築可能にする。
  6. 待機時に複数の独立domain workerでMemoryを整理する。
  7. 再利用可能な成功・失敗・Rule・Skillだけを抽象化してContextStillへ送る。
  8. ContextStillのopaque source referenceから既存Recall責務へ戻れるようにする。
  9. ContextStill停止やMemory worker失敗が通常Chatを停止させない。

4. 非要件

  • 新しいtimeline_events、continuity_streams、Timeline FTSを作らない。
  • raw_recall.rsまたは二つ目のmodel-visible conversation toolを作らない。
  • 内部のConversation、Turn、RunをUser-facing Sessionとして再導入しない。
  • 全Raw履歴を毎TurnのContextへ投入しない。
  • 特定プロジェクトの現在状態をContextStillへ保存しない。
  • Conversation全文、Meeting全文、Tool Result全文をContextStillへ送らない。
  • 一つのEpisodeだけでRuleまたはSkillを自動active化しない。
  • Vector Searchを初期MVPの必須dependencyにしない。
  • Raw conversationのretention policyを変更しない。

8. SAAA SQLite v11

v10はRecall実装で消費済みである。実装開始時にuser_version = 10を確認し、 それ以外ならmigration番号を推測せず本文書を再baselineする。v11はMemory control planeだけを追加し、 conversations、conversation_messages、 conversation_messages_ftsを変更しない。

8.1 continuity_state

CREATE TABLE continuity_state (
  id TEXT PRIMARY KEY CHECK(id = 'primary'),
  canonical_conversation_id TEXT NOT NULL,
  context_policy_version INTEGER NOT NULL,
  capsule_active_revision INTEGER NOT NULL DEFAULT 0,
  capsule_checkpoint_created_at TEXT,
  capsule_checkpoint_message_id TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY(canonical_conversation_id) REFERENCES conversations(id),
  CHECK(
    (capsule_checkpoint_created_at IS NULL AND capsule_checkpoint_message_id IS NULL)
    OR (capsule_checkpoint_created_at IS NOT NULL AND capsule_checkpoint_message_id IS NOT NULL)
  )
);
  • 通常Chatの新規write先を一件だけ指す。UserへIDを公開しない。
  • 既存Conversationをmerge、renumber、delete、copyしない。
  • legacy Conversationは既存Recallにより全件横断検索できる状態を維持する。
  • Coding Task、Meeting等のresource conversationは残せるが、通常ChatのSession UIには出さない。

8.2 memory_source_windows

CREATE TABLE memory_source_windows (
  id TEXT PRIMARY KEY,
  source_ref TEXT NOT NULL UNIQUE,
  start_message_id TEXT,
  end_message_id TEXT,
  source_digest TEXT NOT NULL,
  availability TEXT NOT NULL CHECK(availability IN ('available','deleted')),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY(start_message_id) REFERENCES conversation_messages(id) ON DELETE SET NULL,
  FOREIGN KEY(end_message_id) REFERENCES conversation_messages(id) ON DELETE SET NULL,
  CHECK(
    (availability = 'available' AND start_message_id IS NOT NULL AND end_message_id IS NOT NULL)
    OR (availability = 'deleted' AND start_message_id IS NULL AND end_message_id IS NULL)
  )
);

CREATE TRIGGER conversation_messages_memory_source_tombstone
BEFORE DELETE ON conversation_messages
BEGIN
  UPDATE memory_source_windows
  SET start_message_id = NULL,
      end_message_id = NULL,
      availability = 'deleted',
      updated_at = strftime('%Y-%m-%dT%H:%M:%fZ', 'now')
  WHERE start_message_id = OLD.id OR end_message_id = OLD.id;
END;
  • Profile、Working State、Capsule、Reflection、ContextStill source refの共通provenanceにする。
  • Raw削除時はsource window自体を残し、deletedへ遷移させる。
  • source refはopaqueで、message ID、conversation ID、pathを含めない。

8.3 continuity_capsule_revisions and items

CREATE TABLE continuity_capsule_revisions (
  id TEXT PRIMARY KEY,
  revision INTEGER NOT NULL UNIQUE CHECK(revision > 0),
  status TEXT NOT NULL CHECK(status IN ('building','active','superseded','failed')),
  source_max_created_at TEXT NOT NULL,
  source_max_message_id TEXT NOT NULL,
  source_digest TEXT NOT NULL,
  token_count INTEGER NOT NULL CHECK(token_count >= 0),
  created_at TEXT NOT NULL,
  activated_at TEXT
);

CREATE TABLE continuity_capsule_items (
  id TEXT PRIMARY KEY,
  revision_id TEXT NOT NULL,
  item_kind TEXT NOT NULL CHECK(item_kind IN (
    'active_referent','constraint','open_loop','commitment','recent_decision'
  )),
  value_json TEXT NOT NULL CHECK(json_valid(value_json)),
  status TEXT NOT NULL CHECK(status IN ('active','resolved','superseded','stale')),
  priority INTEGER NOT NULL DEFAULT 0 CHECK(priority BETWEEN -100 AND 100),
  source_window_id TEXT NOT NULL,
  valid_until TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY(revision_id) REFERENCES continuity_capsule_revisions(id),
  FOREIGN KEY(source_window_id) REFERENCES memory_source_windows(id)
);

次revisionは、前回checkpointより後のRawと、まだavailableなactive source windowを読み直して作る。 前revisionの文章だけを要約するsummary-of-summaryは禁止する。新revisionは同一transactionで active化し、旧revisionをsupersededにしてからcontinuity_stateを更新する。

checkpoint順序は(created_at, message_id)の昇順で固定する。 rowidはVACUUM等で永続cursorにならないため使用しない。checkpoint messageが削除済みでも、 保存したtupleより後を選択して再開できることをfixtureで検証する。

8.4 Profile、Working State、Jobs

user_profile_itemsとworking_state_itemsはtyped JSON、status、priority、 validity、source_window_idを持つ。active sourceがdeletedになったitemは投影しない。 inferred Profileはcandidateに留め、User確認なしにUser Coreへ入れない。 

CREATE TABLE memory_reflection_jobs (
  id TEXT PRIMARY KEY,
  job_kind TEXT NOT NULL CHECK(job_kind IN (
    'capsule_refresh','profile_candidate','experience_reflection',
    'working_state_cleanup','outbox_delivery'
  )),
  source_window_id TEXT,
  status TEXT NOT NULL CHECK(status IN (
    'queued','running','completed','skipped','failed','cancelled'
  )),
  attempt_count INTEGER NOT NULL DEFAULT 0,
  lease_until TEXT,
  next_attempt_at TEXT,
  result_code TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,

これに抽象化済みpayloadだけを保持するmemory_outbox、 decision countだけを保持するmemory_decision_events、 Context Health countだけを保持するcontext_projection_eventsを加える。 Raw本文、Recall query、抽象化前後の対応表は保存しない。

9. Sessionless UIとContext Window

9.1 Sessionless normal Chat

  • 起動時はcontinuity_state.canonical_conversation_idを開く。
  • 通常ChatからNew Conversation、Conversation一覧、resume操作を除く。
  • topic shiftは同じcanonical conversationへ書き込み、Memory relevanceだけを切り替える。
  • 旧Conversationを一つの巨大表示へcopyしない。過去の具体会話は既存Recallで横断する。
  • resource conversationを開く操作はresource表示であり、User関係やMemory scopeをresetしない。

9.2 Per-turn ContextEnvelope

ContextEnvelope
├─ policy: trusted, versioned
├─ currentInstruction: live user message, exactly once
├─ userCore: source-backed bounded projection
├─ continuityCapsule: active revision only
├─ workingState: active and relevant only
├─ recentDialogue: bounded historical data
├─ rawContinuityEvidence: recall_conversation output, optional
├─ experienceEvidence: Episode / Rule / Skill, optional and untrusted
└─ provenanceManifest + healthReport
  1. Provider profileから実効Context上限を取得する。
  2. requested output、20% reserve、10% safety marginを入力より先に確保する。
  3. 候補をsource ID、digest、semantic keyでdeduplicateする。
  4. expired、superseded、deleted-source、無関係itemを除外する。
  5. Current messageをRecent dialogueから除き、一回だけlive user roleへ置く。
  6. 過去会話、Recall、Tool Result、ContextStill evidenceをhistorical dataとしてserializationする。
  7. 完成Envelopeを再計測し、Context Healthを実行する。
effectiveContext = providerAdvertisedContext - adapterOverhead
outputReserve    = max(requestedMaxOutput, ceil(effectiveContext * 0.20))
safetyMargin     = ceil(effectiveContext * 0.10)
inputBudget      = effectiveContext - outputReserve - safetyMargin

9.3 Context Health Engine

Provider送信前に次をすべて満たす。

  1. Current instructionはexactly onceで最優先のUser inputである。
  2. projected tokensはinput budget以下で、output reserveを侵食しない。
  3. superseded、expired、deleted-source itemは0件である。
  4. 同じfactまたはinstructionの重複投影は0件である。
  5. 構造化Memoryはsource ref、validity、trust classを持つ。
  6. 過去の命令文はPolicyまたはCurrent instructionを上書きできない。
  7. 直前の完全なturn pairと未完了Tool correlationを途中で分断しない。
Table: Health state
状態 条件 動作
GREEN 全invariantを満たす 送信
YELLOW 修復可能な重複、stale、照応不足 evict / dedup / targeted recall後に再検査
RED budget、reserve、source、instruction trust違反 元Envelopeを破棄してminimal rebuild

REDの元Envelopeは送信しない。Policy、Current、直前pair、critical constraintだけで再構築し、 再検査でもREDならProvider requestを開始しない。

10. Idle Memory Coordinator

jobは「idleになった時」ではなくTurn完了時にdurable enqueueする。実行だけを待機時に行う。 各domainは別job kind、別quota、別retry policyを持つ。 

Turn completion
  ↓ create source window + enqueue independent jobs
queued durable jobs
  ↓ idle eligibility
claim one bounded job
  ↓ run one domain worker
commit completed / skipped / retryable failure
  ↓ re-check foreground activity before next job

10.1 Idle eligibility

  • active Runtime Runが0件
  • 最後のUser inputから30秒以上
  • Meeting capture、transcription、recordingがinactive
  • battery、thermal、network policyを満たす
  • foreground request開始時は新規claimを止め、running jobへcancel signalを送る

10.2 Domain workers

Table: Independent memory domains
domain 入力 出力
Capsule Refresh checkpoint後のRaw + active source atomic Capsule revision
Profile Candidate 明示Preference候補 candidate / NO_MEMORY
Experience Reflection completed source window Episode Candidate / NO_MEMORY
Working State Cleanup TTL、resolved signal expire / supersede
Outbox Delivery sanitized payload ContextStill receipt

一回のidle cycleは一job、最大30秒、LLM call一回、出力2,000 tokenを初期上限とする。 Timeline Index Maintenanceは作らない。既存Recall FTSはv10 triggerで同期される。

11. ReflectionとCandidate

Reflectionの出力はstrict unionとする。

NO_MEMORY
| PROFILE_CANDIDATE
| EPISODE_CANDIDATE(success | failure | mixed | unknown)
  • 雑談、一時的感想、固有事情だけ、再利用不能、根拠不足はNO_MEMORY。
  • Episodeはsituation、action、outcome、lesson、outcome kind、source refを持つ。
  • 成功は再現可能なactionとoutcome、失敗はcauseとavoidanceを必要とする。
  • Reflection outputはCandidateであり、active Memoryの直接writeではない。
  • source windowがdeletedなら新規Reflectionを開始しない。

12. ContextStill拡張

SAAAは抽象化済みCandidateをversioned APIへ冪等に送る。ContextStillのprivate DBへ接続しない。

  "sourceRef": "saaa://memory-source/opaque-id",

  • 同じidempotency keyは同じreceiptを返す。
  • ContextStill側でもsecret、path、project/client/person identifierを再検査する。
  • near duplicateはreviewまたは既存Episodeへmergeし、無条件に増殖させない。
  • ContextStill停止、timeout、5xxはChat失敗へ伝播させない。

13. Rule／Skill Induction

  • Rule Candidateは同じ判断原則を支持する独立Episodeを2件以上必要とする。
  • Skill Candidateは再現可能なworkflowを支持する独立Episodeを3件以上必要とする。
  • failure-only evidence一件ではSkillを作らない。
  • Candidateは既存quality、evidence、finalize、merge lifecycleを通す。
  • 全origin Episodeを保持し、origin欠落のKnowledgeはactive化しない。
  • Procedureを永続化typeとし、context上の表示名はSkillとしてよい。

14. 型別Memory RecallとRaw Drill-down

14.1 既存recall_conversationの固定契約

  • SQLite conversation explorationの唯一のmodel-visible Conversation Toolである。
  • query、relative/absolute time、opaque cursorだけを受ける。
  • 全Conversationを横断してanchorを探し、前後最大2 turn、最大3 windowを返す。
  • 物理Conversation境界はneighbor windowの範囲だけに使用し、anchor検索またはMemory partitionの境界には使用しない。
  • 一Main Turnあたり最大3 calls、出力は保守的に3,000 token以内とする。
  • tool resultはhistorical conversation dataであり、current instructionではない。
  • query本文とresult本文をreceiptへ保存せず、digestとopaque refsだけを保存する。
  • resultをconversation_messagesへ複製せず、Recall自身を次のhit候補にしない。

MVP 3はこの実装を作り直さない。Context Builderから必要時に同じapplication serviceを呼ぶ。 SQLiteを直接読む別resolver、別FTS、別Conversation Toolを追加しない。

14.2 ContextStill typed Memory Tools

Experience、Rule、Skillは取得対象だけでなくContext上の意味が異なる。Agentが目的に合う型を選び、 Context Healthが型ごとのtrustとbudgetを検査できるよう、次の三Toolへ分離する。 詳細なContextStill側の依頼契約は ContextStill MCP 型別Memory Tool改修依頼書を正本とする。

Table: Model-visible Memory Fetch Tools
Tool Memory type Context semantics 主な出力
recall_experience Episode 過去の事例Evidence situation、action、outcome、lesson、outcome kind、source refs
recall_rule Rule 適用候補となる判断制約 rule body、polarity、appliesTo、confidence、origin refs
recall_skill Procedure = Skill 実行候補となる手順 useWhen、workflow、verification、avoid、origin refs
  • 三Toolは共通してquery、opaque projectRef、applicability facets、limitを受け、additionalProperties: falseとする。
  • defaultはactive Memoryのみ、limit 5、最大10件、4,000 token以内とする。
  • outputにはmemoryType、trustClass = untrusted_memory_evidence、 instructionAuthority = none、retrieval mode、degraded reasonsを含める。
  • no-hitはplain textではなく、同じJSON envelopeのitems: []で返す。
  • User Core、Working State、Continuity Capsule、Agent PolicyはTool Fetch対象にせず、Context Builderが自動投影する。
  • 既存search_episodes、fetch_episode、 search_knowledgeは互換呼び出し可能に残す。新規SAAA経路はtyped toolsだけを使う。
  • legacy search_memory / fetch_memoryはLLM server互換Raw memoryであり、SAAAのExperience、Rule、Skill取得へ転用しない。

15. Privacy、Security、Observability

  • SAAA_SESSIONLESS_ENABLEDとSAAA_MEMORY_ENABLEDを独立gateにする。
  • memory.enabledはcanary完了後もdefault OFFとする。
  • Raw query、Raw result、Timeline本文、抽象化前後の対応表をlogへ出さない。
  • 記録するのはjob count、latency、result code、health count、token count、queue depthだけ。
  • Recall tool output、過去user message、Episode/Rule/Skillはuntrusted historical dataとして扱う。
  • ContextStillへ送るpayloadはoutbox保存前に抽象化を完了させる。

17. Stop conditionとRollback

次のいずれかが発生したら次のWork Packageへ進まない。

  • 実装開始時のschemaがv10ではない。
  • v11が既存Conversation、Message、FTS、Recall receiptを書き換える。
  • 新しいTimeline table、Raw FTS、Raw Recall module、二つ目のconversation toolが追加される。
  • Memory tracingのためにmemory::recall外からRaw conversation SQLを実行する。
  • 通常ChatでSession IDの選択が必要なままである。
  • Recallが現在のconversation_idだけへ絞られる。
  • Current instruction重複、reserve不足、sourceなしMemory、RED送信が一件でもある。
  • CapsuleがRawを読まず前版Capsuleだけから更新される。
  • 抽象化前の識別子、path、endpoint、secretがContextStillへ到達する。
  • ContextStill停止が通常Chatを失敗させる。
  • foreground開始後に新しいMemory inferenceを開始する。
  1. memory.enabledをOFFにする。
  2. SAAA_MEMORY_ENABLEDをOFFにしてworkerとoutboxを止める。
  3. Experience Recallを外し、Context Healthと既存Raw Recallを維持する。
  4. Sessionless canaryを止める場合はSAAA_SESSIONLESS_ENABLEDをOFFにする。
  5. v11 Memory tablesは削除せず、v10 Recall schemaとRaw dataをそのまま維持する。
  6. migration integrity違反時だけpre-migration backupへ戻す。
