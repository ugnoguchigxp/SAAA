会話内UIのコードレビューと修正結果

2026-09-12。対象は今回追加した会話内UIと、会話・Provider tool・SQLite・履歴表示との接続部分。初回レビュー、再現テスト、修正、再レビュー、ブラウザーでの操作検証を行った。既存の別作業の差分は保持した。

発見して修正した問題

修正済みの指摘。P1は機能停止・データ再表示の失敗、P2は操作や境界条件の不整合
優先度 問題 修正と検証
P1 深いUIが作成時は通るのに、保存後の読込で拒否される。JSONを参照付きの別記法へ変換する際、深さの数え方が変わっていた。 JSONから直接検証用の構造へ変換し、参照自体は表示階層として数えない。保存・再読込の失敗をテストで再現して修正。保存時のノードIDも従来の表示キーと整合させた。
P1 操作状態キャッシュの上限到達時、新しく読んだUIの状態が最初の購読前に消え、表示が失敗する。 Hostの保持期間を明示的に管理し、表示準備中も回収対象から除く。上限到達と複数Hostの同時読込を回帰テスト。
P1 履歴取得中に最新更新が失敗すると、取得中フラグが解除されず、以後のページ取得が止まる。 会話の世代管理と最新取得の順序管理を分離し、取得完了時の後始末を保証。遅延、失敗、会話切替を含めたテストを追加。
P1 UIの遅延ロード自体が失敗した場合、Host内部の例外処理に届かず、会話全体へエラーが広がる。 遅延ロードの外側にも例外処理を配置。失敗するlazy importを実際に描画し、周囲の会話と保存済み要約が残ることをテスト。
P2 古いページを追加しただけで最新側の未取得ありと判定される。保持上限で落とした行へのcursorも失われ得る。 実際に範囲から除外した端だけを未取得として扱い、上限処理を履歴ストアへ集約。件数、前後方向、先頭到達、最新更新をテスト。
P2 長い未取得期間の後に、古い履歴と新しい末尾だけを結合し、途中の履歴へ到達できない穴ができる。 最新ページの先頭が既存範囲と連続する場合だけ結合。それ以外は最新ページへ置換し、前方取得できる状態に戻す。新着完了通知だけが重なるケースもテスト。
P2 履歴の先頭追加で読んでいる位置がずれる。幅変更時にも高さの全初期化によるずれが生じる。 独自の位置補正を除き、TanStack Virtualのanchor機能を使用。可視行の高さ測定も既存ResizeObserverに一本化。ブラウザーで追加前後のずれが約254pxから0.1px未満になることを確認。
P2 状態保存の版競合が起きると、同じ古い版で再試行し続け、保存できない。 現在の保存状態と版を再読込し、ローカルの変更分だけを重ねて1回再試行。無関係な他方の変更を保持し、再競合・通信失敗は未保存として残す。
P2 初期設定の読込が遅れて返ると、成功済みの有効化操作を古い値で上書きする。 設定の世代を検査し、保存操作を順番に実行。遅延した初期読込と保存失敗後の再操作をテスト。
P2 停止ボタン単独の定義では、部品が必要とするruntime.runsを取得できず、操作が現れない。 Actionsのデータ依存をバックエンドの許可sourceに含める。取得中・失敗・対象なしも表示する。
P2 入力はサイズ内でも、保存時に付加される情報を含めると再読込上限を超え、読めない定義が残る。 保存する最終表現にも64KiB上限を適用し、DBへ書く前に拒否。境界サイズのテストで孤立Viewが残らないことを確認。
P2 同期的な取得失敗でin-flight状態が解放されず、再試行できない。表示解除直後に取得が始まる経路もある。 取得開始をPromise内へ統一し、開始直前にも購読を確認。同期例外後の復旧、開始前の解除、遅延応答の破棄をテスト。
P2 周辺の境界不整合：日本語の入力上限が文字数とbyte数で違う、保存一覧の古い検索応答が除外済み項目を復活させる、仮想化内部の高さキャッシュが蓄積する。 文字数契約を統一し、検索応答にも世代を付与。保持範囲外の計測値を回収する。長い文字列もUIの幅内で折り返す。

検証結果

  • 全体check：型、IPC、整形、Clippy、既存の品質検査を通過。Frontend 251件、Rust 489件が成功。Rust 11件は既存のignore対象。
  • 最後の表示・検索修正後にもtypecheck、Frontend全251件、本番buildを実施。パッケージ版のdesktop smokeも成功した。
  • 履歴150件を保持したまま、先頭へ30件追加して末尾30件を解放するfixtureでも位置を確認。対象メッセージの上端は追加前−154px、追加後−153.9765625px、次の追加後−153.953125px。
  • 幅変更は1000→360→1000px。対象メッセージ上端の差は0.1px未満で、Qwenの絞り込み入力も維持。ブラウザーのerror／warnログはなし。
  • 再レビューでは、今回の修正に対して追加で対処すべき不具合は見つからなかった。これは対象範囲と実施した検証に基づく結果であり、未知の不具合が存在しないという保証ではない。

ログと測定結果はspec/evidence/generative-ui/review/に保存した。実モデルの生成成功率とTauriの詳細な性能測定は前回と同じく未検証で、このレビュー結果で合格扱いに変更しない。
