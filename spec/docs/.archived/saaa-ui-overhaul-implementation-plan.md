# SAAA UI抜本改修計画

- Status: Implemented
- 対象: macOS版SAAA desktop
- 作成日: 2026-09-21
- 対象領域: 会話、メモリ、仕事、記録、監査、設定、Artifact

## 1. 結論

SAAAの画面を、会話を起点とした六つの上部メニューへ再編する。

`会話 / メモリ / 仕事 / 記録 / 監査 / 設定`

上部メニューは左寄せにし、ロゴ、アプリ名、ハンバーガーメニュー、英語の小見出し、説明文を常設しない。画面名が必要なページだけ、本文の直前に小さなタイトルを一つ置く。会話画面にはページタイトルも置かず、メニューの選択状態だけで現在地を示す。

Artifactは独立した常設ページにしない。会話中の成果物、または「仕事」の完了済み項目から開いたときだけ、画面右側を分割して表示する。閉じている間は空き領域を予約せず、主コンテンツが全幅を使う。

今回の改修は見た目だけの変更ではない。現在チャット内に混在している監査、実装ジョブ、動作設定、状態表示を、それぞれの目的に合うページへ移す。会話画面は「読む・入力する・必要な成果物を見る」に集中させる。

## 2. 固定する設計判断

| 項目 | 採用する形 | 採用しない形 |
| --- | --- | --- |
| 主ナビゲーション | 左寄せ上部メニュー | ハンバーガーメニュー、左サイドバー |
| 初期画面 | 会話 | ダッシュボード |
| ブランド表示 | OSのウィンドウ情報に任せ、本文には置かない | SAAAアイコン、SAAAタイトルの常設 |
| ページ見出し | 必要な画面だけ小さなタイトルを1行 | 英語の小見出し、サブタイトル、説明用ヒーロー領域 |
| Artifact | 必要時だけ右側に表示 | 閉じていても右側を空ける、上部に操作を置く |
| メモリ | Personal Stateの可視化 | 手入力メモ、別のメモ用データベース |
| 仕事 | 実行中のキューと、終了済み・成果物 | 完了タスクをキューへ残す |
| 記録 | SQLiteに保存済みのユーザーとLLMのやり取り | 監査イベントやツールログを混ぜた統合タイムライン |
| 監査 | 現在のAudit機能をページ化 | 会話上のモーダル |
| 設定 | 現在の設定項目を維持 | 今回のUI改修に合わせた設定仕様の作り直し |

## 3. 現行実装との差分

### 3.1 再利用できるもの

- 会話本文、仮想スクロール、過去メッセージのページング、ストリーミング表示
- `ArtifactWorkspaceProvider`、複数タブ、改訂表示、差分表示、50%・60%・100%の幅判定
- `personal_state_snapshot`、`personal_source_page`、出典単位の忘却処理
- StewardのGoal、Task、成果物参照とCoding Job
- `CodingSettings.enabled`を含む実装ツール設定
- SQLiteの`conversations`と`conversation_messages`
- TanStack Tableを使ったAudit一覧
- 現在の設定項目と保存処理

### 3.2 変更が必要なもの

| 現在 | 改修後 |
| --- | --- |
| `Surface = chat \| settings` | 六つのトップレベル画面を持つApp Router |
| 会話上部にタイトル、動作状況、モデル、設定ボタン | 左寄せメニューだけを表示 |
| Auditはハンバーガーメニューからモーダル表示 | 「監査」ページとして表示 |
| Coding JobとSteward操作が会話本文の上に常設 | 「仕事」へ移動 |
| 会話ごとの音声動作バーが本文上部を占有 | 入力欄付近の小さな動作ボタンから開く |
| 設定が独立した戻る式画面 | 上部メニューから同じApp Shell内に表示 |
| Artifact Providerが会話画面だけを包む | App Shell全体を包み、仕事の成果物からも開ける |
| 完了済み成果物を後からまとめて探す画面がない | 「仕事 > 完了済み・成果物」から再表示 |
| キュー順が永続化されていない | 並べ替え順を正本へ保存 |

## 4. 画面全体の構造

```text
┌──────────────────────── 主領域 ────────────────────────┬── Artifact ──┐
│ 会話  メモリ  仕事  記録  監査  設定                  │ タブ     閉じる │
├────────────────────────────────────────────────────────┤               │
│                                                        │               │
│ 選択中ページの主コンテンツ                             │ 成果物本文    │
│                                                        │               │
└────────────────────────────────────────────────────────┴───────────────┘
```

Artifactを閉じているときは右列そのものをなくし、主領域をウィンドウ幅いっぱいに広げる。上部メニューは主領域に属する。Artifactが開いているときは右列がウィンドウ上端から始まり、メニューの右側へ状態表示や操作ボタンを置かない。

推奨するDOM構造は次のとおり。

```text
ArtifactWorkspace
├─ PrimaryRegion
│  ├─ TopNavigation
│  └─ ActivePage
└─ ArtifactPanel（開いているときだけ存在）
```

この構造なら、Artifactが開いたときにメニューを含む左側全体だけを縮められる。チャットページの内側へDrawerを後付けする構造より、仕事ページから成果物を開く場合も扱いやすい。

## 5. 共通UI仕様

### 上部メニュー

- 並び順は「会話、メモリ、仕事、記録、監査、設定」で固定する。
- 起動直後は「会話」を選択する。
- 左端から始め、ロゴやタイトル用の余白を設けない。
- 選択中の項目は文字色と下線、または背景色のどちらか一つで示す。
- メニュー右側は空ける。モデル名、接続状態、ユーザーアイコン、設定アイコンを置かない。
- キーボードの左右キーでメニュー間を移動できるようにする。
- 狭い幅では横スクロールを許可する。ハンバーガーメニューへ戻さない。

### ページタイトル

- 会話にはタイトルを表示しない。
- メモリ、仕事、記録、監査、設定には、主コンテンツを見失わない大きさの`h1`を一つだけ置く。
- タイトル直下の説明文は置かない。操作説明が必要なら、該当する入力欄や空状態の近くへ短く表示する。
- 「CONTINUOUS CONVERSATION」のような英語の小見出しは使用しない。

### 状態とエラー

- 正常状態を常時バッジで表示しない。
- 失敗、確認待ち、設定不足など、ユーザーの対応が必要な場合だけ該当箇所に表示する。
- Providerや音声の詳細状態は「設定」または入力欄付近のポップオーバーで確認する。
- 通信中や実行中の状態は、対象の行、入力欄、タスクカードの内部で示す。

## 6. 画面別仕様

### 6.1 会話

会話は起動時の画面であり、最も広い表示領域を使う。

常時表示するもの:

- 会話本文
- 入力欄
- 送信、停止、マイクの操作
- 入力欄付近の小さな「会話の動作」ボタン

条件付きで表示するもの:

- ストリーミング中の回答
- 音声認識中の文字
- 再試行や復旧操作
- セットアップが未完了の場合の案内
- LLMが提示したインラインUIと「Artifactで開く」操作

会話から外すもの:

- ページタイトルとサブタイトル
- ハンバーガーメニュー
- Provider名とローカル・クラウド状態の常設バッジ
- `CodingJobs`と`StewardPanel`
- `ConversationVoiceBehaviorBar`の常設表示

「会話の動作」ボタンは入力欄の末尾側へ置く。押すと、音声出力、聞き取り間隔、会話固有設定のリセットを小さなポップオーバーで操作できる。詳細なProvider設定へ移動する導線はポップオーバー内に置く。

### 6.2 メモリ

新しいメモ機能は作らず、既存のPersonal Stateを可視化する。TanStack Tableによる一覧と、選択項目の詳細ペインで構成する。

一覧の初期列:

| 列 | 内容 |
| --- | --- |
| 内容 | 人が読める形に整えた現在値。長文は1〜2行で省略 |
| 種類 | 目的、制約、未決事項など、既存の`key`から得られる分類 |
| 状態 | active、disputed、expiredなど既存状態の表示名 |
| 根拠 | 関連する出典数 |
| 更新 | 正本に更新時刻がある場合のみ表示。なければ初期版では列を出さない |

操作と挙動:

- 行を選ぶと、右または下の詳細ペインに値、状態、出典を表示する。
- 出典のプレビューから「記録を開く」で元の会話へ移動できるようにする。
- 「忘れる」は既存の`forget_personal_source`を使う。対象範囲と取り消せないことを確認してから実行する。
- 「訂正する」は初期版ではPersonal Stateを直接編集しない。会話画面へ移り、訂正内容を依頼するための入力文を下書きする。これにより、LLMの抽出・根拠・忘却の契約を迂回しない。
- Personal Stateが停止中、契約未確認、削除処理中の場合は、該当する状態だけを表の上へ表示する。

実装では`PersonalStateSection`内に閉じている取得処理を、`personalStateApi`と`usePersonalStateSnapshot`へ分離する。設定画面は有効化や接続状態を扱い、メモリ画面は内容の閲覧と出典操作を扱う。

### 6.3 仕事

ページ内に「キュー」と「完了済み・成果物」の二つのタブを置く。初期表示はキューとする。

#### キュー

表示対象は、受付済み、実行中、確認待ち、停止受付済みなど、まだ終端状態に達していない仕事だけとする。成功、失敗、中止、結果不明として終了した仕事はキューから外す。

各行に表示する情報:

- 並び順
- 仕事の要約
- 状態
- 実行先
- 登録時刻または開始時刻
- 必要な場合だけ、確認、停止、再開などの操作

優先順位の入れ替えは、ドラッグだけに依存しない。「上へ」「下へ」のキーボード操作も用意する。変更後の順序はバックエンドへ保存し、再起動後も維持する。

`steward_tasks`には現在、ユーザー指定の順序を表す値がない。そのため、次のどちらかを実装時に選ぶ。

1. `steward_tasks.queue_rank`を追加し、同一キュー内の順序を保持する。
2. 順序変更履歴が必要なら、専用の順序テーブルを追加する。

初期実装は1を推奨する。並べ替えAPIは対象ID、前後の基準ID、期待revisionを受け取り、競合時は再読込を求める。画面だけで配列を並べ替え、実行順へ反映しない実装は不可とする。

#### Codex SDKの使用許可

キュー上部に「Codex SDKを仕事で使用する」のチェックボックスを置く。新しい設定は作らず、既存の`CodingSettings.enabled`を正本として読み書きする。

- OFFの場合、新しいCodex SDK仕事の受付・実行を開始しない。
- 実行中の仕事を強制停止する設定としては扱わない。OFFへ変更するとき、実行中の仕事があれば影響を説明する。
- 接続先、実行ファイル、モデル、profileなどの詳細は「設定」で扱う。
- `profile !== codex-sdk-v1`の場合は、ラベルを実際の実行方式に合わせるか、Codex SDKを選ぶ設定導線を表示する。表示名と実際のbackendが食い違う状態を作らない。

#### 完了済み・成果物

終了した仕事と、後から再表示できる成果物を一覧にする。成功だけでなく、失敗・中止・結果不明も履歴として残し、状態で絞り込めるようにする。

各行に表示する情報:

- 仕事の要約
- 終了状態
- 終了時刻
- 結果の短い要約
- 成果物の数と種類
- 元の会話を開く操作

成果物を選ぶと、既存のArtifact表示機構を使って右側に開く。会話中に表示された保存済みUI viewと、`steward_task_artifacts`が参照する成果物を同じ一覧からたどれるよう、読み取り用の集約APIを用意する。集約結果は参照情報だけを返し、成果物本文を別テーブルへ複製しない。

### 6.4 記録

初期版はSQLiteに保存されたユーザーとLLMのやり取りを読むための画面に限定する。監査イベント、音声パケット、ツール実行ログ、メモリ生成履歴は混ぜない。

構成:

- 左または上: 会話の一覧。更新日時の新しい順
- 主領域: 選択した会話のユーザー発言とLLM回答
- 検索: 初期版は本文の簡易検索。既存の検索経路を再利用できない場合、ページ内で取得済み範囲だけを検索する
- ページング: 既存の`list_message_window`を再利用する

会話はユーザー発言と、その後に確定したLLM回答を時系列で表示する。system、transcript、内部tool結果は初期表示から除外し、必要になるまでフィルターも追加しない。

記録からメモリの出典へ到達した場合は、対象メッセージを強調する。記録から現在の会話を再開する機能は今回の必須範囲にしない。

### 6.5 監査

現在の`AuditLogPage`をトップレベルページとして再利用する。データ取得、並べ替え、詳細表示、音声パイプライン表示、デバッグ情報のコピーは維持する。

変更するのはページの外枠だけとする。

- モーダルとハンバーガーメニュー経由の導線を廃止する。
- 既存の英語小見出し、説明文、大きなヘッダー余白を削る。
- 小さな「監査」タイトルと更新操作を同じ行に置く。
- テーブルを主コンテンツとして、可能な限り上端から表示する。

### 6.6 設定

保存処理、設定項目、内部タブは維持する。上部の「戻る」、英語小見出し、説明文は削除し、トップレベルの「設定」メニューで現在地を示す。

設定内の左メニューには項目名だけを表示し、常設の詳細文を削る。説明が必要な場合は選択中の設定内容の中へ置く。保存バーは維持する。

Personal Stateの内容一覧は「メモリ」へ移し、設定には有効化、接続、契約状態など、動作を決める項目だけを残す。Codingの詳細設定も設定に残し、「仕事」のチェックボックスと同じ正本を参照する。

## 7. Artifactの仕様

### 表示

- 閉じているときはDOM上の右列と幅予約を持たない。
- 開いたときはウィンドウ右端に表示し、上端から下端まで使う。
- 左側の現在ページは残す。Artifact幅が100%になる狭幅では左側を`inert`にする。
- 既存の50%・60%・100%幅ポリシーを維持する。
- 複数タブ、最大8件、改訂切替、差分表示を維持する。

### 開く場所

- 会話内のインラインUI
- 「仕事 > 完了済み・成果物」
- 将来追加する他ページは、同じ`useArtifactWorkspace`を利用する

### 状態

開いているタブ、選択中タブ、幅はウィンドウ内の一時状態とする。再起動後の復元は今回行わない。トップレベルページを切り替えても、ユーザーが閉じるまでは開いたArtifactを維持する。これにより、成果物を見ながら記録や設定を確認できる。

Artifact本文の正本は既存のUI view、revision、成果物参照に置く。仕事一覧のために本文を複製しない。

## 8. データとAPI

| 画面 | 正本 | 初期実装で必要なAPI変更 |
| --- | --- | --- |
| 会話 | `conversation_messages`、runtime state | 原則なし |
| メモリ | Personal State | 一覧用の型をfrontendへ分離。元会話へ移動するためのmessage IDが不足する場合のみread modelを拡張 |
| 仕事・キュー | Steward Goal/Task、Coding Job | 全会話を対象にしたactive task一覧、永続的な並べ替えAPI |
| 完了済み・成果物 | Steward Task/Artifact、UI view/instance/revision | 終端タスクと成果物参照をまとめる読み取りAPI |
| 記録 | `conversations`、`conversation_messages` | 既存snapshotと`list_message_window`を再利用。件数増加時だけ会話一覧をページング化 |
| 監査 | `audit_events` | なし |
| 設定 | `settings`、Coding Settings | なし。画面間で同じ設定を再取得・更新できるAPI層へ整理 |

新しい一覧APIは、Zodで入力と返却値を検証する。frontendで状態名を推測せず、backendの終端・非終端分類を共有契約として定義する。

## 10. 実装段階

### Phase 0: ベースライン固定

- 現在の会話、Artifact、Audit、設定、Coding Jobのスクリーンショットを保存する。
- 既存の主要テストと`bun run size:check`の結果を記録する。
- 会話送信、ストリーミング、音声、Artifact表示、設定保存の既存動作を受け入れ基準にする。

完了条件: 改修後と比較できる画面とテスト結果が残っている。

### Phase 1: App Shellと上部メニュー

- `AppRoute`を定義し、初期値を`conversation`にする。
- `AppShell`と`TopNavigation`を追加する。
- ブランド、タイトル、ハンバーガーメニュー、右上の状態群を削除する。
- 設定を戻る式画面からトップレベル画面へ変更する。
- Artifact ProviderをApp Shellの外側へ移す。

完了条件: 六つのメニューへキーボードとポインターで移動でき、Artifactを閉じた状態では各ページが全幅を使う。

### Phase 2: 会話の整理

- `CodingJobs`と`StewardPanel`を会話から外す。
- 音声動作バーを入力欄のポップオーバーへ変更する。
- Provider状態はエラー時だけ入力欄付近へ表示する。
- 会話送信、履歴ページング、音声、Artifactを回帰確認する。

完了条件: メッセージと入力欄以外の常設領域がなく、既存の会話機能が維持されている。

### Phase 3: 監査と設定の移設

- Auditをページとして組み込む。
- 旧モーダルと`ChatOverflowMenu`を削除する。
- 設定ヘッダーと内部メニューを圧縮する。
- Personal Stateの閲覧部分を設定から分離する準備を行う。

完了条件: 監査と設定が上部メニューから直接開き、旧導線が残っていない。

### Phase 4: メモリ

- Personal State用API hookを分離する。
- TanStack Table、詳細ペイン、出典表示、忘却操作を実装する。
- 出典から記録へ移動する導線を追加する。
- 訂正依頼を会話の下書きへ渡す。

完了条件: 既存Personal Stateの全項目と出典を確認でき、忘却後の一覧が正本と一致する。

### Phase 5: 仕事

- Coding/Stewardの取得処理を会話から仕事ページへ移す。
- キューと完了済み・成果物のタブを追加する。
- Codex SDK使用許可を既存設定へ接続する。
- queue rankと並べ替えAPIを追加する。
- 完了済み仕事と成果物参照の集約APIを追加する。

完了条件: 非終端の仕事だけがキューに現れ、終了時に自動で消え、完了済みタブから結果とArtifactを開ける。並び順は再起動後も維持される。

### Phase 6: 記録

- 会話一覧とメッセージ表示を追加する。
- 既存のページングを再利用する。
- メモリの出典から対象記録へ移動できるようにする。

完了条件: SQLiteに保存済みのユーザー発言とLLM回答を、会話単位で過去へさかのぼれる。

### Phase 7: 仕上げと旧実装削除

- 使われなくなったCSS、翻訳、コンポーネントを削除する。
- 720px前後の狭幅、キーボード操作、フォーカス復帰を確認する。
- 初期バンドルと描画性能をベースラインと比較する。
- 全体テストとdesktop smokeを実行する。

完了条件: 旧ヘッダー、旧メニュー、重複したデータ取得、到達不能な画面が残っていない。

## 13. 全体の受け入れ条件

1. 起動すると会話が開き、上部左側に六つのメニューが指定順で表示される。
2. SAAAのアイコン、SAAAタイトル、ハンバーガーメニュー、常設サブタイトルが表示されない。
3. Artifactを閉じている間、右側に空白や非表示パネル用の幅が残らない。
4. Artifactを開くと右端の上から下まで表示され、左側に不要な操作が増えない。
5. 会話画面はメッセージと入力欄を中心に使い、仕事・監査・設定の常設UIを含まない。
6. メモリ画面はPersonal Stateを一覧と出典で確認でき、別のメモ正本を作らない。
7. 仕事のキューには非終端の仕事だけが表示され、終了すると自動で消える。
8. 完了済み・成果物から、過去に会話で表示したArtifactを再度開ける。
9. Codex SDKの使用許可が既存設定と一致し、画面ごとに異なる値を持たない。
10. 記録画面で、SQLiteに保存されたユーザーとLLMのやり取りを会話単位で確認できる。
11. 現在のAuditと設定の機能が失われない。
12. キーボードだけでメニュー、表、タブ、Artifactの開閉を操作できる。

## 15. 実装時に確定する点

次の項目は、Phase 0のベースライン採取時に数値を確認して決める。

- 上部メニューの高さと左右余白
- 会話本文と入力欄の最大幅
- メモリ詳細ペインを右に置ける最小幅
- 仕事キューをカードと表のどちらで表示するか。情報密度とキーボード並べ替えを比較して決める
- 記録の初回取得件数と追加読込件数
- Artifact 50%・60%表示を切り替える実幅の閾値

これらは情報構造を変える判断ではない。固定した設計判断を維持したまま、実機の読みやすさと操作性で調整する。
