SQLite Single Writer実装計画 — Rust-owned reusable Writer and concurrent Readers

0. 文書の役割

  • Status: Reviewed / Implementation-ready v3
  • Created: 2026-08-31
  • SAAA baseline: 0ec8019 + working tree
  • Database baseline: PRAGMA user_version = 14
  • Settings document baseline: schema_version = 13
  • Shipping target: Tauri desktop（macOS、Windows、Linux）
  • 対象: Rust SQLite ownership、Writer、Reader、起動・終了、永続化test

本文書は、SAAAが所有するsaaa.sqlite3への書込みを、単一のSAAAプロセスが保持する Rust製SqliteWriter一インスタンスへ集約するための実装契約である。 実装担当がWriter方式、プロセス排他方式、Reader分離、移行順序を追加で選択しないよう、 型、所有権、起動順序、変更範囲、test、acceptanceを本文書で固定する。

完了の定義はDBW-00〜DBW-09を順に完了し、Section 13のAcceptance Criteriaをすべて満たすことである。本計画ではRust実装とpagination IPCを変更する。 table / column / data形式とuser_versionは変更せず、Section 8.4で固定する expression index一件だけを追加する。

1. 結論と固定判断

SAAA process A
├─ DatabaseOwnerGuard ── exclusive OS advisory lock
├─ Arc<SqliteWriter> ─── the only read-write Connection
│  └─ Mutex<rusqlite::Connection>
└─ SqliteReaders ──────── two persistent read-only Connections
   ├─ Reader 1
   └─ Reader 2

SAAA process B
└─ DatabaseOwnerGuard acquisition fails
   └─ must exit before Connection::open(saaa.sqlite3)
  1. Writerは新しいchild processまたはsidecarにしない。Tauri main process内で一度だけ生成した Arc<SqliteWriter>をcommand、background task、runtimeで使い回す。
  2. SqliteWriterだけがmain databaseのread-write rusqlite::Connectionを所有する。Connectionのclone、再open、pool化を禁止する。
  3. Writer内部のMutex<Connection>で同一プロセス内の書込みを直列化する。 AppStateやfeature runtimeへ生のConnectionまたはMutexを公開しない。
  4. DBを開く前にDatabaseOwnerGuardがOS advisory lockを取得する。 二つ目のSAAAプロセスはmain databaseを一度もopenせず、安定した database-already-ownedエラーで終了する。
  5. ReaderはSqliteReadersがSQLITE_OPEN_READ_ONLYと PRAGMA query_only=ONで起動時に2本だけ生成して再利用する。Reader同士および ReaderとWriterはWAL上で並行実行でき、read transactionは結果materialize直後に閉じる。
  6. read-modify-write、起動reconciliation、migration、整合性snapshotはWriter上で実行する。 純粋なSELECTだけをReaderへ移す。
  7. 専用Writer thread、async channel、read-write connection pool、新しいORMは導入しない。 read-only poolは固定2本を上限とし、既存の同期rusqlite APIをblocking worker上で使う。 長い前処理はWriter / Reader lock取得前に終える。
  8. 本変更ではschema versionを上げない。table / column / データ形式は変えず、Reader ownership、 cursor IPC、Section 8.4の一indexとqueryだけを変える。

2. 現状と変更理由

Table: Verified current SQLite architecture

AppState.connection: Arc<Mutex<Connection>> src-tauri/src/lib.rs 書込みは直列だが、read-write capabilityが全featureへ露出している

SQLite/WALは同時にcommitできるWriterを一件へ制御するが、SAAAの設計要件はSQLiteの競合解決へ 依存することではない。DBのread-write capabilityを一つのRust objectと一つのowner processへ 閉じ込め、他の処理はそのobjectを再利用することを要件とする。

3. Goals / Non-goals

3.1 Goals

  1. main DBのread-write Connectionをprocess内に一件だけ存在させる。
  2. 二つ目のSAAAプロセスがmain DBへ接続する前に拒否される。
  3. すべての書込みが同じArc<SqliteWriter>を再利用する。
  4. Readerをread-only capabilityとして分離し、同時SELECTを許可する。
  5. 既存transaction、migration、backup、reconciliationの意味を維持する。
  6. source scanとprocess testで、将来の直接open・直接共有の回帰を検出する。

3.2 Non-goals

  • SQLiteからclient/server databaseへ変更しない。
  • Writerを別daemon、sidecar、network serviceにしない。
  • すべてのSQLを一ファイルまたは巨大なcommand enumへ移動しない。
  • 新しいtable、column、trigger、settings documentを追加しない。
  • Section 8.4のnextCursor以外のUI、IPC payload、business ruleを変更しない。
  • 外部の任意processによるDB file改変をsecurity boundaryとして完全に防止しない。
  • Readerを3本以上へ動的拡張する汎用pool、またはread-write connection poolを導入しない。

4. 必須不変条件

  • DBW-I01: production codeでmain DBをread-write openできる場所は persistence/sqlite/writer.rsだけである。
  • DBW-I02: DatabaseOwnerGuard取得前にmain DB、-wal、 -shmへ接続または更新しない。
  • DBW-I03: SqliteWriterはprocess lifetime中に一インスタンスだけ生成し、 cloneするのはArcだけとする。
  • DBW-I04: Connection、Mutex<Connection>、 MutexGuard<Connection>をWriter methodの外へ返さない。
  • DBW-I05: Writer lockを保持したまま.await、HTTP、child process待機、 audio処理、User選択待ちを行わない。
  • DBW-I06: ReaderはOS level read-only flagとquery_only=ONの両方を使う。
  • DBW-I07: read-modify-writeは一回のWriter critical sectionまたはtransaction内で完了する。
  • DBW-I08: process crashでOS lockは自動解放され、次回起動に手動cleanupを要求しない。
  • DBW-I09: lock contention、SQLite error、diagnosticsへdatabase absolute pathを出さない。
  • DBW-I10: schema version、table / column、既存row、backup形式、readiness reader契約を変えない。追加indexはSection 8.4の一件だけとする。

5.2 DatabaseOwnerGuard

src-tauri/Cargo.tomlへfs2 = "0.4"を追加し、 FileExt::try_lock_exclusiveでdatabase pathと同じdirectoryの saaa.sqlite3.writer.lockをlockする。lock file handleをguard内に保持し、 SqliteWriterがdropされるまで解放しない。

  1. database parent directoryを既存ルールで作成・検証する。
  2. lock fileをread/write、createでopenする。Unixではmode 0600を固定する。
  3. regular file、non-symlink、current ownerを検証する。
  4. try_lock_exclusiveを一回だけ実行する。待機やretryをしない。
  5. WouldBlockまたはlock競合をDatabaseOpenError::AlreadyOwnedへ変換する。
  6. lock取得後にだけmain databaseのConnection::openへ進む。

lock fileは正常終了時もunlinkしない。unlock後の残存fileは無害であり、unlinkと別processのopenが競合して 別inodeへ二重lockする事故を避ける。process crash時はOSがfile handleのlockを解放する。

5.3 SqliteWriter

pub(crate) struct SqliteWriter {
    connection: std::sync::Mutex<rusqlite::Connection>,
    _owner: DatabaseOwnerGuard,
}

impl SqliteWriter {
    pub(crate) fn open(path: &Path) -> Result<Self, DatabaseOpenError>;

    pub(crate) fn write<T>(
        &self,
        operation: impl FnOnce(&mut Connection) -> Result<T, String>,
    ) -> Result<T, String>;

    pub(crate) fn write_transaction<T>(
        &self,
        behavior: TransactionBehavior,
        operation: impl FnOnce(&Transaction<'_>) -> Result<T, String>,
    ) -> Result<T, String>;

    pub(crate) fn read_serialized<T>(
        &self,
        operation: impl FnOnce(&Connection) -> Result<T, String>,
    ) -> Result<T, String>;
}
  • writeは既存repositoryが自分でtransactionを開始する移行用・複合operation用であり、 自動transactionを開始しない。
  • write_transactionは新規または単純な複数statement operationへ使う。既存transactionを 二重に開始しない。
  • read_serializedはbackup、migration判定、read-modify-writeの先行SELECTなど、Writerと同じ Connectionで読む必要がある場合だけ使う。通常SELECTには使わない。
  • poisoned Mutexは既存のDatabase lock unavailable相当の安定したerrorへ変換する。
  • operation完了時にguardを必ずdropし、Connection referenceをclosure外へ持ち出さない。

5.4 SqliteReaders

#[derive(Clone)]
pub(crate) struct SqliteReaders {
    lanes: Arc<[Mutex<Connection>; 2]>,
    next_lane: Arc<AtomicUsize>,
}

impl SqliteReaders {
    pub(crate) fn open(database_path: &Path) -> Result<Self, String>;
    pub(crate) async fn read<T, F>(
        &self,
        operation: F,
    ) -> Result<T, String>
    where
        T: Send + 'static,
        F: FnOnce(&mut Connection) -> Result<T, String> + Send + 'static;
}

openはWriterのmigrationとinitialize完了後、起動時にread-only Connectionを2本だけ openする。readはspawn_blocking内でround-robinにlaneを選び、 lock待ち時間をmetric化して再利用する。async executorとUI threadでrusqlite処理を直接実行してはならない。 steady stateでConnectionをopen / closeしてはならない。statementは prepare_cachedを使い、各operationのread transactionはquery結果をmaterializeした直後に commitしてWAL checkpointを妨げない。 

PRAGMA query_only = ON;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

open flagはOpenFlags::SQLITE_OPEN_READ_ONLYだけを必須とする。Reader connectionを feature codeへ公開せず、UI threadから同期readを呼ばない。Reader lane failure時は そのlaneだけを一度reopenし、連続3回失敗した場合はDB readを明示的にfailする。無制限retryは禁止する。

5.5 AppState wiring

struct AppState {
    sqlite_writer: Arc<SqliteWriter>,
    sqlite_readers: SqliteReaders,
    data_directory: PathBuf,
    // existing non-database state...
}

connection: Arc<Mutex<Connection>>は削除する。background workerへ渡すのは Arc<SqliteWriter>またはSqliteReadersだけとする。 SqliteWriter自体をcloneせず、必ず同じArc allocationを共有する。

6. 起動、実行、終了sequence

6.1 Startup

resolve application_database_path
  ↓
create/validate parent directory
  ↓
DatabaseOwnerGuard::acquire(lock path)
  ├─ AlreadyOwned → stable startup failure; DB is not opened
  └─ acquired
       ↓
Connection::open(main DB read-write) exactly once
       ↓
backup_before_migration
       ↓
initialize_database / migration / reconciliation
       ↓
SqliteWriter owns Connection + guard
       ↓
open exactly two read-only Connections → SqliteReaders becomes available
       ↓
load startup snapshots
       ↓
app.manage(AppState)

backup_before_migration、initialize_database、 database-ready audit eventはowner processだけが実行する。二つ目のprocessはbackup directory、 main DB、WALへ触れない。

6.2 Runtime

  1. network、validation、audio/model処理、JSON encodeはWriter lock取得前に行う。
  2. DBへ渡すowned valueを準備してからsqlite_writer.writeを呼ぶ。
  3. read-modify-writeは一closureにまとめ、途中でlockを解放しない。
  4. transaction commitまたはrollback後、closureから即時returnする。
  5. 結果を使う非DB処理はWriter lock解放後に行う。

6.3 Shutdown

  1. 新規turn、meeting、voice sessionを停止する。
  2. 既存のmeeting reconcile、situation quality flushを同じWriterで完了する。
  3. 新規readを停止し、実行中read完了後に二本のReader Connectionをcloseする。
  4. background taskが持つArc<SqliteWriter>をdropする。
  5. 最後のArc dropでConnectionをcloseし、その後DatabaseOwnerGuardをunlockする。
  6. lock file自体は削除しない。

shutdown timeoutでprocessが終了してもOSがlockを解放するため、次回起動にstale PID判定やlock file削除は 不要である。

8. Reader分離

8.1 初回にReaderへ移すoperation

  • settings、provider、routingの純粋なload
  • conversation/message listとpagination
  • audit event listとdiagnostics用SELECT
  • situation history、metrics、review snapshotの純粋なSELECT
  • voice profile snapshotのうちreconcileやwriteを伴わないSELECT

8.2 Writer側に残すread

  • migration version判定とmigration backup
  • run/message、job claim、state transitionのread-modify-write
  • backup source connection
  • 書込み直後の返却値を同一transactionから構築するquery
  • startup reconciliation中のquery

8.3 Hidden writeの除去

現行get_app_snapshotはensure_primary_conversationによりSELECT command内で INSERTしうる。primary conversationのensureをstartup Writerへ固定し、snapshotを純粋なReader operationへ 変更する。同様に、名前がload、get、snapshotでもcleanup、reconcile、 INSERT OR IGNOREを行う関数はWriter側へ分類する。

8.4 Conversation message keyset

現行のCAST(created_at AS INTEGER) + deep OFFSETは削除し、次のexpression indexと二つのprepare_cached statementへ固定する。本文をindexへ複製するcovering indexは DB sizeとwrite amplificationを増やすため禁止する。 

CREATE INDEX IF NOT EXISTS idx_conversation_messages_conversation_created_ms
ON conversation_messages(conversation_id, CAST(created_at AS INTEGER) DESC, id DESC);

-- first page
SELECT id, conversation_id, role, content, created_at
FROM conversation_messages INDEXED BY idx_conversation_messages_conversation_created_ms
WHERE conversation_id = ?1
ORDER BY CAST(created_at AS INTEGER) DESC, id DESC
LIMIT ?2;

-- next page; cursor = (created_at_ms, id)
SELECT id, conversation_id, role, content, created_at
FROM conversation_messages INDEXED BY idx_conversation_messages_conversation_created_ms
WHERE conversation_id = ?1
  AND (CAST(created_at AS INTEGER), id) < (?2, ?3)
ORDER BY CAST(created_at AS INTEGER) DESC, id DESC
LIMIT ?4;

Rustは取得したDESC列の末尾（最古row）から次cursorを作ってから、一度だけreverseして画面の時系列順へ返す。公開cursorは { version: 1, createdAtMs: i64, messageId: string }をbase64url JSONへencodeしたopaque nextCursorとする。decode後にprimary keyでmessage ID、conversation ID、createdAtMsの一致を 検証し、改ざん・別conversation・不正versionをinvalid-cursorで拒否する。 cursorなしはfirst statement、ありはnext statementだけを使い、OFFSETへfallbackしない。 EXPLAIN QUERY PLANに当該indexのSEARCHがあり、USE TEMP B-TREEが ないことをarchitecture testで固定する。

process testはcurrent_exe()で同じtest harnessのhidden helper testを起動する。 owner readyはstdoutの一行、終了はstdin EOFで制御し、固定sleepに依存しない。

12.3 Architecture tests

  • productionのConnection::open / open_with_flagsは persistence/sqliteと別fileを対象とするbackup.rsだけをallowlistする。
  • AppStateとruntime structのConnection fieldを禁止する。
  • productionのArc<Mutex<Connection>>を禁止する。
  • readiness runnerのreadonly: trueとquery_only=ONをpinする。
  • conversation paginationのproduction SQLでOFFSETを禁止し、Section 8.4のindex定義をexact matchでpinする。

14. Rollout、stop condition、rollback

14.1 PR boundaries

  1. PR 1: DBW-00〜DBW-02。新型とtestだけを追加する。
  2. PR 2: DBW-03〜DBW-05。全write pathを切り替える。
  3. PR 3: DBW-06〜DBW-08。Reader分離と回帰gateを完成する。
  4. Acceptance run: DBW-09。desktop evidenceを記録する。

PR 2の途中で旧AppState.connectionと新Writerを同時にproductionへ残さない。 同じbinary内でmain DBの二接続Writerを作る移行期間は禁止する。

14.2 Stop conditions

  • 同一binaryでmain DBのread-write Connectionが二件必要になった。
  • Writer lockを保持したままnetworkまたはUser待ちを避けられない。
  • 既存atomic transactionを複数Writer callへ分割する必要が生じた。
  • process lockが対象OSのいずれかでcrash後に自動解放されない。
  • Readerへ移したoperationにhidden writeまたはreconcileが見つかった。

Stop時は対象ticketをmergeせず、operationをWriter側へ残すか、transaction境界を再設計してから再開する。 single Writer invariantを緩めて進行しない。

14.3 Rollback

  • table / columnとschema versionを変更しないため、直前binaryへcode rollbackできる。追加expression indexは旧binaryが無視でき、rollback後も残してよい。
  • 残ったsaaa.sqlite3.writer.lockは削除不要で、旧binaryは無視する。
  • running processがある状態でlock fileを削除しない。
  • データ不整合を検出した場合は既存SQLite backupから復元し、原因判明まで新binaryを停止する。
  • Reader分離だけに問題がある場合は、pure readをread_serializedへ戻してWriter一意性を維持する。

15. Definition of Done

  • main DBのread-write openがSqliteWriter一箇所だけである。
  • 一つのprocessだけがDatabaseOwnerGuardを保持できる。
  • AppStateと全runtimeからraw Connection/Mutexが消えている。
  • 全write pathが同じArc<SqliteWriter>を再利用する。
  • pure readがread-only Connectionで並行実行できる。
  • 二重起動、crash recovery、migration race、Reader/Writer concurrency testがpassする。
  • 既存feature、schema、backup、readiness contractに回帰がない。
  • Section 13.3のrepository gateとSection 13.2のdesktop acceptanceがpassする。
