1. 結論

User text / microphone
        ↓
Conversation Turn Coordinator（唯一の状態正本）
  ├─ Capture Session → local VAD / bounded buffer → one final ASR request
  ├─ LLM Turn        → effective capability → typed request → verified finish reason
  └─ Presentation    → text completion → optional speakable text → queued TTS output
        ↓
Typed outcome / retry action / truthful route status
        ↓
Chat UI + runtime ledger + non-content diagnostics
  1. Frontendの複数refを会話状態の正本にしない。Backendのruntime runと、純粋なTurn state machineが同じrun ID、segment ID、message IDを共有する。
  2. LLMのmax_tokens = 256とenable_thinking = falseの固定注入を廃止する。 ユーザーの希望とProvider能力から一つのEffective Completion Policyを作り、通常実行と接続テストで共用する。
  3. finish_reasonを終端契約にする。length、未知値、終端欠落を成功として保存、表示、 読み上げしない。
  4. ASR discoveryを発話ごとに行わない。設定保存または明示的な再テストで解決し、warm pathは一発話一回の transcription POSTだけにする。疑似partialのための二重文字起こしは削除する。
  5. 既定の音声会話はhalf-duplexとする。TTS再生中はASRへ音声を送らず、マイク操作はTTS停止完了後に開始する。 Target Speaker Filterが健全な場合だけ、verified barge-inを明示的に選べる。
  6. LLM、ASR、TTS、設定の失敗を別の型として扱う。TTS失敗からLLM promptを再送しない。 LLM再試行でも既存User messageを再利用し、会話へ同じUser messageを追加しない。
  7. Settingsは実際に変更できる値だけをcontrolとして表示する。固定adapterは説明文、動的値は選択肢、 未実装値は表示しない。readinessとlocal/cloud表示はBackendの直近probe結果から描画する。
  8. TTSはmodel deltaを12〜64文字で逐次process起動する方式をやめ、意味境界で分割して一つ先をrenderする。 画面表示用Markdownと読み上げ用plain textを分離する。
  9. System Contextに入力modality、応答言語、簡潔さ、音声向け表現、曖昧な文字起こしの確認規則を追加し、 固定fixtureと実Provider evalで品質を採点する。

3. Scope

3.1 達成すること

  1. LLM回答の完全性、Provider能力、fallback、失敗理由を実行時とUIで一致させる。
  2. 一発話一transcriptionを通常経路にし、ASR待ち時間とnetwork request数を計測可能にする。
  3. 音声capture、endpoint、ASR、LLM、TTS、再開を一つの決定的な状態遷移にする。
  4. TTS自己音声がUser messageになる経路を、既定設定で0件にする。
  5. ユーザーがLLM、ASR、TTSの実効設定、接続状態、data locationを確認できるようにする。
  6. 各失敗に、対象を重複実行しないretry actionを一つだけ提示する。
  7. Text表示とSpeech表現の双方で、会話の正確さ、自然さ、簡潔さを評価する。

3.2 非要件

  • Cloud ASRまたはCloud TTSの追加。
  • ASR engine自体の再学習、speaker verification modelの変更。
  • WebSocket streaming ASRを、batch API上の疑似streamとして実装すること。
  • 複数のAssistant音声を同時再生すること。
  • 完全なacoustic echo cancellationをLLM、VAD、promptだけで実現したと主張すること。
  • Meetingの多話者UX全体の再設計。共通ASR clientとcancellationの修正だけを適用する。
  • 会話内容、raw PCM、transcriptをanalyticsへ送信すること。

5. Target State Architecture

5.1 状態の正本

ConversationTurn
  id: runId
  input: { messageId, origin: text | voice, segmentId? }
  phase:
    idle | listening | endpointing | transcribing | generating
    | presenting | completed | cancelled | failed
  llm: { providerId?, location?, finishReason?, outputStarted }
  speech: { sourceMessageId?, ttsRunId?, state }
  issue: ConversationIssue?

VoiceCaptureSession
  id: captureSessionId
  generation: monotonically increasing integer
  armed: boolean
  phase: idle | listening | finalizing | pausedForSpeech | failed
  activeSegmentId: string?
  boundedPreRoll + boundedCurrentUtterance + queue(max 2)

React stateは上記snapshotの表示用projectionである。非同期callbackはcapture generationとsegment IDが一致する場合だけ状態を更新する。古いpreview、ASR、TTSの完了callbackが 新しいturnを閉じることを禁止する。

5.2 Turn taking policy

Table: Audio turn modes
Mode 適用条件 TTS中のcapture 期待挙動
half-duplex 既定。Filter OFFまたは不健全 pauseしbufferを破棄 Mic操作でTTS停止を待ち、150〜250ms drain後に新規captureを開始
verified-barge-in Target Speaker Filterがreadyかつユーザーが選択 local verificationまで継続 本人speech確定後にTTSを停止し、その後だけASRへ送る

WebViewへechoCancellation: true、noise suppression、auto gainをidealで要求し、 実際のMediaTrackSettingsを表示する。ただしAEC有効表示を自己音声除外の証明には使わない。

6. Settings Contract

6.1 LLM

  • Conversation routeへmaxOutputTokensを追加する。既定2048、許容256〜8192、 Provider上限を超える場合は保存時またはresolve時に明示的にclampして実効値を表示する。
  • reasoningはopenai-effort、qwen-thinking、noneの能力としてresolveする。 noneでは選択controlをdisabledにし、「未対応」と表示する。
  • qwen-thinkingではlowをthinking off、medium/xhighをthinking onへ一箇所で写像する。 reasoning_effortとthinking offを同時に送る矛盾したrequestを禁止する。
  • Primaryが利用不能でfallbackを使った場合、実際に選ばれたProviderとlocationをChatへ表示する。

6.2 ASR

  • LLM hostとの暗黙共有を廃止し、Voice SettingsにASR hostを独立して保存する。
  • Providerは現時点でLAN batch ASR一つであるためselectorに見せない。「Built-in LAN ASR adapter」と説明する。
  • modelは/v1/modelsと/healthが一致した値だけを選択肢として保存する。
  • language、timeout、endpoint、last checked、healthを表示する。credentialやraw errorは表示・保存しない。
  • 文字起こし後の動作をauto-sendまたはreview-before-sendから選べるようにする。 reviewでは確定transcriptを編集可能なcomposerへ置き、明示送信までLLMを開始しない。
  • 設定保存時にBackendでresolveし、成功したEffective ASR Configurationをruntime cacheへ反映する。

6.3 TTS

  • say -v ?をboundedに解析するIPCでvoice一覧を取得し、free-text入力をselectへ置き換える。
  • rodio/cpalからoutput deviceを列挙し、保存したoutputDeviceIdで実際にstreamを開く。
  • rateを120〜260 words-per-minute相当のbounded値として追加し、試聴と通常読み上げで共用する。
  • autoSpeak booleanをoff、voice-input-only、allへ移行する。 新規installationはvoice-input-only、既存trueはallへ互換移行する。
  • output deviceまたはvoiceが消えた場合はSystem defaultへ黙ってfallbackせず、degraded表示と選択修正を求める。

6.4 Settings migration

  1. 実装開始時に次の空きSettings schemaとDB versionへrebaseする。本文書baselineではSettings 10、DB 13を候補とするが、同時進行migrationがあれば番号を取り直す。
  2. Compatibility build Aはschema 9と新schemaの両方を読み、schema 9だけを書く。Feature build Bで新schemaを書く。 これによりBからAへのbinary rollbackを成立させる。
  3. migrationはtransaction内で行い、旧値、変換後値、default適用をfixture testで固定する。
  4. unknown field、public HTTP ASR、制御文字、存在しないreasoning mode、範囲外token/rateをfail-closedにする。

7. LLM Runtime Contract

7.1 Effective Completion Policy

User preference
  + route maxOutputTokens
  + resolved provider capabilities
  + context-window output reserve
  = EffectiveCompletionPolicy
      { maxOutputTokens, reasoningProtocol, reasoningValue, stream: true,
        toolsEnabled, timeoutMs }

Direct OpenAI-compatible、Dynamic LAN、LARMは同じ型を受け取る。JSON生成を各adapterへ散在させない。 Provider固有parameterはcapabilityで許可された場合だけadapterが追加する。

7.2 Finish reason

Table: Completion terminal semantics
finish reason 結果 永続化 UI / TTS
stop completed Assistant messageを保存 完成表示、TTS継続
tool_calls 次のtool round tool exchangeのみ 回答完了にしない
length failed / partial-output 完成Assistant messageとして保存しない partial表示、TTS停止、「続きを生成」action
content_filter failed / policy 完成Assistant messageとして保存しない bounded説明、通常retryを出さない
missing / unknown / stream EOF failed / protocol 完成Assistant messageとして保存しない 接続問題、同じProviderへのretry

[DONE]はtransport終端にすぎず、直前までに有効なfinish reasonが観測されて初めて成功する。 non-stream JSONも同じclassifierを通す。

7.3 Production-shaped probe

  1. 実行時と同じURL、auth、no-proxy、request builder、stream parserを使う。
  2. 短いstream completionでdelta、finish reason、[DONE]を確認する。
  3. toolsを使うrouteでは副作用のないprobe toolを一件渡し、tool callを一roundだけ検証する。
  4. Dynamic LAN/LARMはallocation取得、data-plane生成、releaseまで完了して初めてreadyにする。
  5. 結果はready | degraded | unavailable、checkedAt、latency、capability summaryとして返す。

8. ASR Runtime Contract

8.1 Request budget

Table: ASR network budget
状況 許可request 上限
Settings resolve / Test GET /v1/models、GET /health、probe transcription 各1回
Warm utterance POST /v1/audio/transcriptions 一発話1回
Cache invalidation recovery models、health、同じaudioの再POST 一発話につき一回だけ。loop禁止

現行previewAudioによる2秒PCMのbatch transcriptionは削除する。Serverが将来正式なstreaming endpointを提供するまで、UIは「Listening」「Transcribing」を表示し、仮transcriptを装わない。

8.2 Capture and buffer bounds

  • speech未検出時は最大500msのring pre-rollだけを保持する。
  • 一発話は最大120秒または16MB相当の小さい方で強制終了し、ユーザーへ分割を促す。
  • segment queueは最大2件とし、drop時はsegment ID付きのcontent-free metricとUI通知を残す。
  • finalize中に次endpointが来た場合はpending finalizeを一件記録し、guard returnで消失させない。
  • stop/unmount/settings changeはcapture generationを進め、古いcallbackを無効にする。

8.3 Cancellation

  • models、health、upload送信、response bodyの全awaitを同じRunCancellationでselectする。
  • AppStateで一つのconfigured HTTP clientを共有し、発話ごとのclient生成をやめる。
  • cancel完了後200ms以内にFrontendをidleまたはlisteningへ戻す。遅延完了は表示を更新しない。
  • ASR再試行用PCMはmemory内に最大2分保持し、成功、破棄、conversation変更、app終了でzero/dropする。

8.4 Network safety

  • ASR endpointはprivate HTTP originだけを許可し、redirectを禁止する。
  • DNS名は接続時に解決した全addressがloopback、link-local、private、unique-localのいずれかであることを確認する。
  • DNS再解決またはconnection reuseでpublic addressへ変化した場合はrequestを送らずcacheをinvalidにする。
  • diagnosticsへhost、IP、transcript、audio hashを残さず、provider IDとbounded failure codeだけを残す。

9. TTS Runtime Contract

9.1 Speakable text

画面へ保存するAssistant contentは変更しない。別の純関数toSpeakableTextが、Markdown構造を 読み上げ向けplain textへ投影する。

  • code blockとinline codeは既定で「コードは画面をご覧ください」に一度だけ置換する。
  • URLは削除し、link labelが自然言語ならlabelだけを残す。
  • heading、bullet、table delimiter、引用記号、絵文字variation selectorを発声しない。
  • 数字、単位、句読点、固有名詞は原文を保ち、内容を要約または改変しない。
  • 空になった場合はTTSを開始せず、Text回答はcompletedのままにする。

9.2 Render-ahead pipeline

Model deltas
  → sentence accumulator（24 min / 120 target / 240 max characters）
  → speakable text
  → render queue(max 2)
      ├─ chunk N playback
      └─ chunk N+1 synthesis in parallel
  → one persistent output stream
  → completion / cancel
  • punctuation boundaryを優先し、URL、括弧、数値を途中で切らない。
  • 同じsource responseのchunk間無音p95を150ms以下にする。
  • render queueを2件に制限し、LLMが速い場合もtemp fileとprocessを無制限に増やさない。
  • cancelはactive playback、queued render、synthesis process、temp fileを同じsession IDで停止する。
  • Text completionとSpeech completionを別outcomeにし、Speech失敗でTextを失敗へ戻さない。

10. User Response and Interaction Contract

10.1 Conversation response policy

System Contextへ以下を追加し、入力値はJSON dataとしてescapeしたまま扱う。

  1. ユーザーの主言語に合わせ、答えを先に述べる。指定がなければ1〜4短段落を既定とする。
  2. voice inputでは、不要な見出し、長い列挙、URL読み上げを避け、耳で追える文にする。
  3. ASR transcriptを事実として扱うが、意味が一意に定まらない場合だけ短く確認する。
  4. 聞き取れなかったと断定したり、存在しないconfidenceを説明したりしない。
  5. 名前は自然な必要時だけ使い、毎回答の呼びかけを禁止する。
  6. 最新情報はtool結果へ基づき、失敗時は推測しない。Textにはsourceを残し、TTSはURLを読まない。
  7. 途中で切れた回答の続きを生成する際、既出部分を繰り返さず直後から続ける。

StartTurnInputへinputOrigin: text | voiceと presentationMode: text | text-and-speechを追加し、promptがUI状態を推測しないようにする。

11. Typed Error and Retry Contract

type ConversationIssue =
  | { scope: "llm"; code: LlmIssueCode; runId: string; inputMessageId: string;
      retry: "retry-response" | "continue-response" | "none" }
  | { scope: "asr"; code: AsrIssueCode; segmentId: string; audioRetainedUntil?: string;
      retry: "retry-transcription" | "record-again" | "none" }
  | { scope: "tts"; code: TtsIssueCode; sourceMessageId: string;
      retry: "retry-speech" | "choose-output" | "none" }
  | { scope: "settings"; code: SettingsIssueCode;
      retry: "open-settings" | "test-connection" | "none" };
  1. retry-responseは既存input_message_idを使う新runを開始し、User messageをinsertしない。
  2. continue-responseは未完了contentをcontextへ一時追加し、重複禁止instructionと十分なtoken budgetで続ける。
  3. retry-transcriptionは保持中の同じsegment PCMだけを再送し、LLMを開始しない。
  4. retry-speechは保存済みAssistant messageから新しいTTS runだけを作る。
  5. UIはissueのretryに対応するbuttonだけを表示し、文字列prefixで挙動を分岐しない。

  • fake TTS renderer/outputでrender-ahead順序、cancel、device loss、temp cleanupを検査する。
  • generated IPC bindingsとFrontend schemaのexhaustive switchをipc:checkで固定する。

18. Definition of Done

  • R-01〜R-13に未解決または「後で対応」が残っていない。

  • 会話品質が90点以上でhard violation 0である。
  • full check、Spec check、migration/rollback、実機matrix、soakがPassする。
  • Section 4を実測値で再採点して90点以上になり、release evidenceへ記録される。
