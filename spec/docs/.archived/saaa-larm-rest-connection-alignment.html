3. Adapter contract

  1. 一意なIdempotency-KeyとttlSeconds: 300、 allowFallback: false、deploymentPolicy: existing-onlyでConnectionを作成する。
  2. pendingとprobingをtimeout・cancel可能なbounded pollで待つ。
  3. ready後のclaimにはIdempotency-Keyを付けない。
  4. audience、model、expiry、connection identityを検証し、claimされた configuration.fields.baseURL、configuration.fields.model、 credential.tokenだけから推論clientを構成する。
  5. claimされたsemantic health URLを短期bearer tokenで確認する。
  6. stream: true、SSE、非空completion、[DONE]を必須とする。
  7. 成功、失敗、cancelの全経路で独立したbounded DELETEを実行し、204を成功とする。
  8. 401、409、410、429、503を明示的失敗として扱う。LLM server routeは設定保存時と実行時の両方で 別Providerへのfallbackを禁止する。
  9. boot epoch変更またはConnection expiryはstaleとして扱う。renew時は再claimとsemantic health確認後に 短期tokenとOpenAI client設定を更新する。

4. Secretと証跡の境界

  • 長期secretはLARM_API_TOKENだけを使用する。
  • management token、connection signing key、/etc/larm/larm.envを要求・取得しない。
  • Provider短期tokenはConnection lifetimeだけメモリ内で保持し、drop時にzeroizeする。
  • token、Authorization header、claim response全体、prompt、completion本文を記録しない。
  • claimされたbase URL、model、semantic health URL、expiryを固定設定またはdiskへ保存しない。
