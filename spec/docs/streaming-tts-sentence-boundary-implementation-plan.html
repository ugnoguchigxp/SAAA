1. 採用判断

採用する方式は「10文字固定分割」ではなく、10文字を最初の発声候補になる最小値とし、 自然な句読点でチャンクを確定するadaptive sentence boundary方式である。 

LLM append-only deltas
        ↓
TurnEventHub（canonical検証後にSpeech即時 / UI latest-winsへ分岐）
        ↓
StreamingSpeechSession
  ├─ raw Markdown accumulator
  ├─ protected-range scanner
  ├─ sentence boundary chunker
  ├─ speakable-text projection
  └─ bounded slots（rendering 1..3 / ready 0..3 / in-player 0..2、30秒 / 16 MiB以内）
        ↓
ordered playback + adaptive parallel synthesis
        ↓
one output stream / complete / cancel / fail

最初の自然な文が確定した時点でTTS合成を開始し、LLMのmessageCompletedは待たない。 一方で、語、URL、Markdown、数値、括弧の途中では切らず、最終イベントで残りを一度だけflushする。

2. Goals / Non-goals

2.1 Goals

  1. 回答全文の完成前に、最初の自然な文から読み上げを開始する。
  2. 読み上げ対象の欠落、重複、順序逆転を0件にする。
  3. 句読点、Markdown、URL、数値、括弧を考慮し、不自然な位置で切らない。
  4. 再生中に次チャンクを合成し、チャンク間無音を抑える。
  5. 停止、割り込み、Provider失敗、画面遷移、app終了でsession全体を確実に取消す。
  6. Text回答の成否とSpeechの成否を分離し、TTS失敗で完成済みTextを失敗へ戻さない。

2.2 Non-goals

  • LLM Provider、prompt、回答内容、ASR endpointingの変更は行わない。
  • 単語単位、token単位、10文字固定での逐次発声は実装しない。
  • LLMがまだ出力していない内容を予測してTTSへ渡さない。
  • full-duplexや未検証のbarge-inを同時に導入しない。half-duplexを維持する。
  • ユーザー向けSettings項目、Database migration、Settings schema更新は追加しない。
  • 実Providerのstreaming audio protocolは前提にしない。既存のtext-to-audio契約を使う。

4. 固定する契約と不変条件

  1. Append-only: 一つのProvider attemptが送るAssistant deltaは追加専用として扱う。 Providerはoutput開始後にfallbackしない現行policyを維持する。
  2. Single ownership: chunk確定位置、queue、active playback、cancel tokenの正本は BackendのStreamingSpeechRuntimeだけが持つ。
  3. At-most-once enqueue: 一つのchunkSeqをrender queueへ二度入れない。
  4. Ordered playback: 再生はchunkSeqの昇順だけを許可する。
  5. Bounded resources: rendering <= 3、ready <= 3、 in_player <= 2、audioは30秒または16 MiBの早い方、raw textは64,000文字、 artifactはsession所有directoryだけに制限する。
  6. Text authority: 永続化されたAssistant messageが最終的な画面表示の正本であり、 Speech失敗や取消で書き換えない。
  7. Half-duplex: 最初の音声再生前にcaptureを一度停止し、最後のchunk終了後または session取消完了後に一度だけ再開する。チャンク間では再開しない。
  8. No content diagnostics: metricとlogへ回答本文、chunk本文、音声hashを残さない。

5. Target Architecture

5.1 Ordered Turn Event Hub integration

Provider eventは親計画のTurnEventHubでsequence、dedupe、terminalを検証し、 canonical deltaをTTSへ先に、capacity 1のprojectionをUIへ後から配送する。SpeechはUI enqueueやpaintを待たない。全LLM経路は同じvalidated eventを使い、TTSへfinal本文のcloneを渡さない。 

#[derive(Clone)]
struct TurnEventHub {
    ui: UiLatestProjection,
    speech: Option<SpeechSessionHandle>,
}

#[derive(Clone)]
struct CompletionProof {
    content_bytes: usize,
    content_sha256: [u8; 32],
    finish_reason: FinishReason,
}

impl TurnEventHub {
    fn accept(&self, event: ValidatedTurnEvent) -> Result<ProviderAck, HubFailure> {
        if let Some(speech) = self.speech.as_ref() {
            match &event {
                ValidatedTurnEvent::Delta { text, .. } => speech.try_append(text)?,
                ValidatedTurnEvent::Completed { proof, .. } => {
                    speech.finish(proof.clone());
                }
                ValidatedTurnEvent::Cancelled { .. } | ValidatedTurnEvent::Failed { .. } => {
                    speech.cancel(SpeechCancelReason::SourceTurnEnded);
                }
                _ => {}
            }
        }
        // capacity 1の未ACK batchとpending suffixへmergeするだけ。WebView paintは待たない。
        self.ui.try_publish_latest(event);
        Ok(ProviderAck::accepted())
    }
}

SpeechSessionHandle::try_append、finish、cancelは短いlock更新と Notify::notify_oneだけを行う。append拒否はTextを失敗させず、そのSpeech Sessionだけを bounded failureへ移す。内部の合成・queue失敗も独立したSpeechEvent::Failedとして通知する。 UIのChannel send、ui.batch.applied、React commit、paintはProvider ACK条件に含めない。 UI channel切断時はそのclient projectionとSpeech Sessionを同じgenerationで取消すが、別runへ波及させない。 Started、ProviderSelected、ProviderFailed、 ActivityはSpeech stateを変更せずUIへだけ送る。LLM providerとTTS providerを混同しない。 preparing eventとruntime_runs insertはstart_turn command境界でsession supervisorが一度だけ実行する。

5.2 StreamingSpeechRuntime

AppStateへArc<StreamingSpeechRuntime>を一つ持たせる。runtimeは同時に 一つのactive Speech Sessionだけを許可する。新しいuser turnまたはreplay開始時は旧sessionの停止完了を待つ。 runtimeのnext_generation: AtomicU64をsession作成時だけfetch_add(1)し、 sessionのgenerationはterminalまで不変とする。cancel時にUI向けgenerationを変更しない。

constructorにはArc<Mutex<Connection>>、data directory、 Arc<SituationRuntime>、SpeechEventBroker、RendererPort、PlaybackPort、enabled boolを渡す。 runtimeからArc<AppState>を保持せず循環参照を作らない。test constructorはin-memory DBとfake portsを同じ引数へ渡す。

lock保持中にnetwork request、process wait、audio playbackを行わない。lock下ではstate更新と slot操作だけを行い、workerへ所有権を移してから非同期処理する。renderingと readyは各最大3件、in_playerは再生中1件と先読み1件の最大2件である。 ready / in-player / rendering reservationの合計は30秒かつ16 MiBを超えない。claim時のduration予約は min(30_000, max(1_000, speakable_graphemes * 150)) msへ固定し、render後はWAVE実測値へ 置換する。実測値への置換で30秒を超えるartifactは再生せずaudio-budget-exceededでSpeechだけを failする。artifact writerはsession共有のbyte semaphoreから64 KiB単位でpermitを取得してから書き、 16 MiBを物理的に超える書込みを同じfailureへ変換する。permitはartifact削除時にだけ解放する。raw delta用の非同期message queueは作らず、source_textを64,000文字でboundedに保つ。

phaseはsession全体のUI lifecycleであり、renderとplaybackの同時進行はslotで表す。 terminal phaseからの遷移は禁止する。最初のaudio sampleを観測するまではaudioStartedを送らないが、 permit ack後はPlayerへappendして次renderを開始してよい。 各state transition後はcancel / failure、次に input_closed && consumed_byte == source_text.len() && all_slots_emptyの順で terminal predicateを評価し、該当しない場合だけ上表のnon-terminal phase更新を行う。

runtimeはlockを長時間保持しないis_active() -> boolを公開する。 meeting/commands.rsとsave_voice_enrollment_sampleは、旧 tts_process.is_some()またはstreaming_speech.is_active()なら既存のblock errorを返す。 最初のPlaybackObservation::StartedでAudioState::SaaaSpeaking、terminal cleanup完了後に AudioState::Silentを一度だけ設定する。app shutdownはlegacy child停止より先に streaming_speech.shutdown()を呼び、Section 7.5のStopAckとthread joinを実行する。

sessionごとにTokio supervisor taskを一つだけspawnする。supervisorは Notify、最大3件のJoinSet<RenderResult>、Harness resolve handle、 playback observation receiver、一つのidle Sleep、一つのcapture-ack Sleep、cancellation tokenを tokio::select!する。rendering slotをclaimした時だけrender taskをspawnし、完了handleを JoinSetへ格納する。並列数は初期値2とし、直近8 chunkの ceil(p95 synthesis time / median audio duration)を1〜3へclampして更新する。 実効値はrouteがadvertiseするmaxConcurrentSynthesisとの最小値で、未指定時は1とする。 maximum-performance profileは2以上を必須とし、満たさないauto-speak routeを明示的にunsupportedにする。 renderer完了用の別channelとdelta message queueは作らない。

5.3 Renderer / Playback worker

trait RendererPort: Send + Sync {
    fn render(&self, job: RenderJob)
        -> futures_util::future::BoxFuture<'static, Result<RenderedChunk, SpeechFailureCode>>;
}

trait PlaybackPort: Send + Sync {
    fn start_session(&self, session_id: &str, generation: u64) -> Result<(), SpeechFailureCode>;
    fn append(&self, chunk: RenderedChunk) -> Result<(), SpeechFailureCode>;
    fn stop(&self, session_id: &str, generation: u64) -> Result<(), SpeechFailureCode>;
}

supervisorはArc<dyn RendererPort>とArc<dyn PlaybackPort>だけに依存する。 production portと#[cfg(test)] fake portは同じstate machineを通る。既存 futures-utilのBoxFutureを使い、trait用だけにasync-traitを追加しない。

  1. chunkerが確定したraw Markdown chunkをRustのvoice_text::text_for_speechへ渡す。
  2. 空になった候補はsource範囲だけcommitし、chunkSeqを消費せず次候補を評価する。
  3. 非空候補はrenderingへclaimした時点でsource範囲とchunkSeqを確定する。
  4. 最初の非空候補claimでplayer_started = trueにし、 PlaybackCommand::StartSessionをrender task spawnの直前に一度だけ送る。device openとTTS合成を並行する。
  5. 各renderer taskは一件のWAVE artifactを合成し、成功後にchunkSeq付きでreadyへ移す。
  6. 最初のreadyでFrontendのcapture停止ackを待ち、ack後にPlayerへappendする。
  7. chunk N再生中もadaptive concurrencyまで後続を並列renderする。Playerへのappendは chunkSeq順とし、再生中+先読みの2件を超えない。
  8. ObservedSourceが最初と最後のsampleを観測し、開始・完了・gap metricを通知する。

Cloud TTSは一つのchunkについて既存endpointからWAVEを全量受信し、session directoryへ chunk-{seq:08}.wavとして保存する。System TTSはtokio::process::Commandで say [-v VOICE] -o PATH --file-format=WAVE --data-format=LEI16@22050を起動する。 configured voiceがdefaultなら-vを省略し、それ以外は既存 validate_voice成功後に指定する。本文はcommand argumentではなくstdinへ書く。stdinは書込後にcloseし、stdout / stderrはnull、 kill_on_drop(true)とする。exit statusが非0ならartifactを削除してrender-failedにする。 Cloud artifactはcreate_newとmode 0600で作る。Systemはprivate session directory内でsymlink_metadata(path)がNotFoundであることを確認してからsayへpathを渡し、 成功後にregular fileかつnon-symlinkを検証してmode 0600へ設定する。親directoryはmode 0700で作成する。cancel時はSystem childをkillし、Cloud requestを cancellation tokenで中止する。

session IDはBackendでspeech_{UUID}として生成し、既存validate_identifierを通す。 artifact directoryはdata_directory/tts-cache/stream-{session_id}、file名は chunk-{chunk_seq:08}.wavへ固定する。startup cleanupはtts-cache直下の stream-speech_で始まるreal directoryだけを対象にする。symlinkと非directoryは削除せず、pathを含まない 固定warningを一度記録して残りのcleanupを続ける。 旧tts-*.wavcleanupはCompatibility中そのまま残す。

session directoryは既存tts-cacheの安全性確認後にcreate_dirで新規作成し、既存path、 symlink、非directoryならsessionをinternalでfailする。create_dir_allで既存の中間pathを 暗黙受理しない。

5.6 Fixed playback dependency

rodio = { version = "=0.22.2", default-features = false, features = ["playback", "wav"] }

6. Sentence Boundary Contract

6.1 初期値

Table: Chunking thresholds
値 初期値 意味
firstMin 10 speakable graphemes 最初のstrong boundaryを発声可能にする最小長
steadyMin 24 speakable graphemes 2件目以降の短すぎる断片を抑える目安
target 120 speakable graphemes strong boundaryがない場合にweak boundaryを選び始める長さ
hardMax 240 speakable graphemes 句読点がなくてもboundedにする上限
idleFlush 400ms LLM delta停止時、weak boundary済み断片を早めに確定する時間

文字数はUTF-8 byteやUTF-16 code unitではなくUnicode graphemeで数える。閾値は実機計測前の初期値であり、 Section 15のcorpusを変えずに比較して調整する。ユーザー向け設定にはしない。

6.2 Accumulator state

struct SentenceAccumulator {
    consumed_byte: usize,
    scanned_byte: usize,
    scanner: ScannerState,
    delimiters: Vec<Delimiter>,
    deferred_strong: bool,
    candidates: VecDeque<BoundaryCandidate>,
    first_chunk_claimed: bool,
    idle_generation: u64,
}

struct BoundaryCandidate {
    end_byte: usize,
    class: BoundaryClass,
}

raw文字列はSpeechSession.source_textだけが所有し、accumulatorはその文字列への UTF-8 byte offsetだけを持つ。consumed_byte <= scanned_byte <= source_text.len()を常にassertする。削除や先頭切り詰めは行わず、session終了時に文字列全体をdropする。 これによりoffset補正とdelta再送用queueを不要にする。64,000文字の上限判定は source_text.chars().count()で行い、超過時はspeech-sync-lostではなく internalでSpeechだけを停止する。

6.3 Boundary class

Table: Boundary classification

boundaryの認識規則は次で固定する。

  1. 日本語の。！？は保護範囲外なら、そのgrapheme末尾をstrongにする。
  2. ASCIIの.!?は、後続が「空白、改行、入力末尾、閉じdelimiter列の後の空白または入力末尾」 だと1文字look-aheadで確認できた時だけstrongにする。次delta待ちの末尾記号は候補化を保留する。
  3. .の前後がASCII digitなら小数・versionの一部として扱う。 :と,の前後がdigitの場合も時刻・桁区切りとしてweak候補にしない。
  4. \r\nは一つ、単独\rまたは\nも一つのstrongにする。 連続改行は末尾までを一候補にまとめる。
  5. 、,;:；：とUnicode空白はweakにする。ただし数値内部、URL、Markdown保護範囲を除く。
  6. safeは保護範囲外のgrapheme末尾であり、ASCII英数字同士、連続片仮名同士、combining sequence内部はsafeにしない。

6.4 Scanner state / protected range

  • 行頭の3個以上の`または~でfenced codeを開始し、同じmarkerを 開始数以上並べた行で閉じる。inline codeは1個または2個の`を同数で閉じる。
  • [label](destination)と![label](destination)は、開始角括弧から destinationの閉じ括弧まで全体を保護する。destinationが来ない角括弧は通常delimiterとして扱う。
  • http://、https://、www.は、大文字小文字を無視して scheme開始から空白または<>"までをURLとして保護する。末尾の 。！？.,!?はURLから外して再走査する。
  • URL autolink以外の<から次の>まではHTML tagとして保護する。 completionまで閉じなければ未閉じdelimiterと同様に末尾flushだけを許可する。
  • 対応delimiterは() [] {} 「」 『』 “ ” ‘ ’とASCII "である。ASCII 'は英語contractionと衝突するためdelimiterにしない。 ASCII "はURL・code外でtoggleする。
  • delimiter内で見つけたstrongは即確定せず、同じnesting levelを閉じるgrapheme末尾へ移して候補化する。 weakはdelimiter内では候補化しない。未閉じdelimiterはcompletion時にだけ末尾flushを許可する。
  • delimiter stackとMarkdown depthは最大64とする。65段目を検出したらscannerを続行せず internalでSpeechだけをfailする。deferred_strongは最も外側の開きdelimiter内で strongを一件以上見つけた印であり、stackが空になる閉じdelimiter末尾をstrong候補にしてclearする。
  • grapheme列挙には既存dependencyのunicode-segmentationを使い、byte offsetは必ず grapheme_indices(true)から得る。

scannerはscanned_byte直前までを反映したstateであり、確定済み範囲を再走査しない。 入力末尾がhttp://、https://、www.、![、code markerの prefix、単独\r、look-ahead未確定のASCII .!?なら、その候補の先頭で走査を止め、 scanned_byteを進めない。次deltaまたはfinishで同じbyteから再開する。保留suffixは最大8 ASCII byteである。これによりdelta境界に依存するlookbehindと候補deduplicationを不要にする。

6.5 Selection algorithm

speakable_len(end_byte)は voice_text::text_for_speech(&source_text[consumed_byte..end_byte])のgrapheme数である。 最初の非空chunkだけminをfirstMin、以後はsteadyMinにする。候補選択は claim capacityがある間、次の優先順で一件ずつ行う。 

select_next(reason)
  1. eligible strongをend_byte昇順に走査し、speakable_len >= minの最初を返す
  2. reason == Idle なら、speakable_len >= minの最後のweakを返す
  3. 現在長 >= targetなら、speakable_lenが[min, target]に入る最後のweakを返す
  4. 現在長 >= hardMaxなら、speakable_lenが[min, hardMax]に入る最後のweak、
     なければ最後のsafeを返す
  5. reason == Completionなら、残りのraw末尾をmin未満でも返す
  6. それ以外はNone

保護範囲がhardMaxをまたぐ場合は範囲を途中で切らず、閉じた直後にstep 4を再評価する。 したがってhardMaxはspeakable textの通常時上限であり、閉じていないURL・code・delimiterの raw長だけは一時的に超えられる。全体の64,000文字上限は超えられない。

6.6 append / idle / finish

append(delta)
  1. deltaが空なら何もしない
  2. source_textへdeltaを一度だけappendし、scannerを進める
  3. idle_generationを+1し、generation値をcaptureした400ms timerを一つarmする
  4. rendering / ready / audio budgetが許す間、select_next(Append)をclaimする

idle(timer_generation)
  1. session generation、idle_generation、input_closedを照合する
  2. stale timerなら何もしない
  3. capacityが許す間、select_next(Idle)をclaimする

finish(completion_proof)
  1. input_closedならduplicate terminalとして何もしない
  2. content_bytesとincremental SHA-256をsource_textへ照合する
  3. 不一致なら全slotとplayerをcancelし、speech-sync-lostで終了する
  4. finish_reason == lengthなら未claim tailを消費済みにしてflushせず、既claim chunkだけdrainする
  5. finish_reason == stopならEOFをscannerへ通知し、保留suffixをcompletion候補として閉じる
  6. input_closed = trueにし、stopだけcapacityが空くたびselect_next(Completion)を繰り返す

proof不一致時に、すでに読んだ内容を取り消すことはできない。全文を自動で最初から読み直すと重複するため、 Textを正本として残し、ユーザーの「読み上げを再試行」で完成済みmessageを最初から読めるようにする。

claimしたraw範囲がprojection後に空ならconsumed_byteだけ進め、chunk sequenceを消費せず 同じworker tick内で次候補を評価する。非空ならSection 7のClaimedへ遷移する。全chunkのraw source rangeは重複せず昇順で、 finishReason=stopでは最終的にsource_text.len()までを一度だけcoverする。 finishReason=lengthでは未claim tailを発声しない。欠落・重複はrange propertyで隠さない。

candidate claim時はconsumed_byte = selected.end_byteへ進め、 end_byte <= consumed_byteの候補をすべてpop_frontする。 scanned_byteとscanner stateは全文上のoffsetのまま維持し、既に走査したsuffixを巻き戻さない。

idle用にdeltaごとのtaskをspawnしない。session supervisorが一つのpinned tokio::time::Sleepを所有し、非空appendを観測するたび reset(Instant::now() + 400ms)する。Sleep発火時はcapture済み idle_generationとlock下の現在値を比較してからselect_next(Idle)を呼ぶ。

6.7 Speakable-text projection

product実装はsrc-tauri/src/voice_text.rs::text_for_speech一つだけとし、新旧TTS経路、 chunkerの長さ計測、replayが同じ関数を呼ぶ。変換順を次で固定する。

  1. 閉じたfenced code全体を空文字へ置換する。言語依存の省略メッセージは挿入しない。
  2. Markdown image / linkはdestinationを除き、alt / labelだけを残す。
  3. inline codeはbacktickだけを除き、内容を残す。
  4. 行頭のheading、blockquote、unordered / ordered list markerを除く。
  5. emphasis / strike markerの* _ ~とHTML tagを除く。
  6. autolinkとbare URLを除く。
  7. emoji graphemeを除く。
  8. 改行を含む連続Unicode whitespaceをASCII space一つへ畳み、先頭末尾をtrimする。

locale判定は行わない。閉じたMarkdown / URL / HTMLをまたいでchunkを切らないSection 6.4と組み合わせ、 text_for_speech(text_for_speech(raw)) == text_for_speech(raw)、およびSection 6.6の compositional propertyを満たす。TS fixtureは期待値をこの契約へ更新してRust testへ移植する。

7. Render / Playback Contract

7.1 Queue bounds

raw unclaimed text: source_text[consumed_byte..]（64,000文字の全体上限内）
rendering:           BTreeMap<chunkSeq, ChunkMeta>（最大3）
ready:               BTreeMap<chunkSeq, RenderedChunk>（最大3、完了順は任意）
in_player:           BTreeSet<chunkSeq>（再生中+rodio待機、最大2）

確定済みraw chunk用の別queueは作らない。次chunkをclaimできる条件はrouteがReady、 rendering.len() < adaptive_concurrency、ready.len() < 3、かつ reserved_audio_ms + candidate_duration_reservation <= 30_000で、byte semaphoreに64 KiB以上の 空きがあることとする。条件を満たさない間も LLM deltaはsource_textへ追記し、scannerだけを進める。render完了順に関係なくreadyへ chunkSeq付きで格納し、next_playback_seqだけをPlayerへappendする。 slot解放通知でSection 6.5を再評価する。 

debug_assert!(
    session.rendering.len() <= 3
        && session.ready.len() <= 3
        && session.in_player.len() <= 2
        && session.reserved_audio_bytes <= 16 * 1024 * 1024
        && session.reserved_audio_ms <= 30_000
);

このassertをclaim、render完了、append、Finished / Aborted、cancelの各state transition直後に置く。

7.2 Chunk lifecycle / commit point

Candidate
  → Claimed(source rangeとchunkSeqを不可逆に確定、chunkQueued publish)
  → Rendered(artifact検証済み、ready slotへ格納)
  → Appended(Playerへappend、in_playerへ移動)
  → Started(ObservedSourceが最初のsampleを返す、audioStarted publish)
  → Finished(ObservedSourceがEOFを観測、slot解放、artifact削除)
  • consumed_byteとnext_chunk_seqはClaimedへの遷移時だけ進める。 render失敗後に同じ範囲を自動claimし直さない。
  • rendererはWAVE header、decode可否、非空sampleを検証してからRenderedを返す。 Cloud responseの上限は既存TTS body上限、timeoutは既存Cloud TTS timeoutを再利用し、値を複製しない。
  • ObservedSourceは最初のnext()でStarted、Noneを返す時にFinishedを supervisorへ一度だけ送る。EOF前dropはAbortedを送り、Finishedとして数えない。
  • artifact guardはObservedSourceが所有し、Finished / Aborted / decode失敗の全経路で削除する。EOFではartifact削除後にFinished、StopではPlayerと全sourceをdropして artifact削除後にStopAckを送る。session directoryは全guard drop後にruntimeが削除する。

7.3 Playback thread

enum PlaybackCommand {
    StartSession { session_id: String, generation: u64 },
    Append { session_id: String, generation: u64, seq: u32, wav_path: PathBuf },
    Stop { session_id: String, generation: u64 },
    Shutdown,
}

app setupで名前付きOS threadを一つ生成し、容量5のstd::sync::mpsc::sync_channelで commandを受ける。このthreadだけがMixerDeviceSinkとPlayerを所有する。 StartSession時にdefault deviceを未openならopenし、新しいPlayerを作る。 Appendはsession ID / generation / 期待seqを検証してthread内でfileをopen・decodeし、 ObservedSourceで包んでappendする。古いcommandはartifactを削除して無視する。 supervisorはlock外からtry_sendする。outstanding commandはStartSession 1 + Append 2 + Stop 1 + Shutdown 1の最大5件であり、それ以上を生成しない。channel満杯または切断なら playback-unavailableでsessionをfailする。playbackからsupervisorへのobservation channelは容量8とし、active source最大2件からStarted / FinishedまたはAborted、StopAck、device failureの最大6件だけをtry_sendする。

StartSessionとAppendは同じFIFO command channelを通るため、Appendはdevice openとPlayer作成の後に処理される。 device open失敗後のAppendはartifactを削除して無視し、supervisorへdevice failureを一度送る。非空chunkを一件も claimしないsessionはStartSessionを送らない。cancel時にplayer_started == falseならStop / StopAckを省略し、 cancel_to_silence_ms = 0とする。

7.4 Render-ahead

  1. 初期concurrency 2でchunk 0と1をclaimし、独立taskでrenderする。
  2. chunk 0がRenderedになりcapture ackを受けたらPlayerへappendする。
  3. chunk 1が先に完了してもreadyへ保持し、chunk 0より先にappendしない。
  4. Playerには再生中と次chunkの最大2件を入れ、空slotへ常にnext_playback_seqをappendする。
  5. render / ready / audio budgetが空いたら次chunkをclaimし、適応concurrency 1〜3を維持する。
  6. LLM完了後もrender/playbackが残っていればSpeech SessionだけDrainingを継続する。

7.5 Cancellation ordering

enum SpeechCancelReason {
    UserStop,
    NewTurn,
    Replay,
    ConversationChanged,
    ClientGone,
    ClientReplaced,
    Shutdown,
    SourceTurnEnded,
}
User stop / accepted new user turn / replay / conversation switch / unmount / shutdown
  → cancel_requested = trueにし、以後の新規claimを禁止
  → cancellation tokenを発火
  → network synthesisを中止
  → System say childをkillしてwait
  → PlaybackCommand::Stopを送りPlayer::stop
  → lock外で同じgenerationのStopAckを最大500ms待つ
  → queued audioとraw accumulatorを破棄
  → ObservedSourceとready artifactをdrop
  → session directoryを削除
  → runtime_runsをcancelled / failedへ確定
  → Backendがcancelled eventを送信
  → Frontendが必要な場合だけmicrophoneを再開

supervisorだけがこの順序を実行し、元のsession generationでterminal eventを一度だけpublishする。 二回目以降のcancel、worker完了、active session ID / generationと一致しないcallback、cancel token発火後の callbackはno-opにする。Frontendはstop command返却だけで停止済みとみなさず、対象sessionの cancelled | completed | failedをgeneration guard付きで受けてUIを確定する。 StopAck timeout時はplayback-failedへ変換し、app shutdownでは既存3秒grace内でplayback threadをjoinする。500msは故障時のhard timeoutであり、Section 15の通常時p95 200ms目標は維持する。

  • 新しいstart_turnを受理したらpresentation modeに関係なく旧Speech Sessionを先に停止する。
  • replay開始時も旧sessionを停止し、停止terminal後に新sessionを作る。
  • 同じsourceのvalidated Completed { CompletionProof }はcancelではなくinput close、ProviderFailedはno-opである。
  • 会話切替、window shutdownはcancel triggerである。capture開始だけをbarge-inとして扱わない。
  • meeting開始は既存policyを維持し、legacy TTSまたはstreaming sessionがactiveなら MEETING_POLICY_TTS_BLOCKED: Stop speech and retry.を返す。meetingを開始してからSpeechをcancelしない。

8.1 Turn開始

StartTurnInput.presentationMode === "visual-and-spoken"をBackendがSpeech Session生成の 明示条件として使う。FrontendはautoSpeakからpresentation modeを決める現行責務だけを持ち、deltaごとにTTS commandを呼ばない。feature flagが無効、presentation modeがvisual、meetingがTTSをblockする、またはSpeech subscriberが未接続ならstreaming用TurnEventHub.speech = Noneとし、Text turnは従来どおり開始する。sessionはprovider attemptではなく論理source runに一つ作る。 TTS routing settingsはsession作成時に既存selected_tts_route相当の関数で一度だけsnapshotし、そのTTS provider IDをruntime_runsへ保存する。System / Cloudは直ちにReady、Harnessは ResolvingHarness { address }で開始し、supervisorが既存 resolve_service_cancellable(address, "tts", cancellation)を一度だけawaitする。返った ServiceDescriptorを現行と同じprovider-harness-ttsの CloudTtsProviderSettingsへ変換し、Harness snapshotへ固定する。Harness解決をLLM start_turn開始の前でawaitしない。routeの既存timeout_msもsessionへ一度だけsnapshotする。 LLMのProviderSelectedではTTS routeを変更しない。 output前fallbackでも同じsessionを維持する。

route_max_concurrencyはSystem / Cloudを3、HarnessをServiceDescriptorの maxConcurrentSynthesis（1〜3、欠落時1）へ固定する。最大性能profileのauto-speakは 2以上を必須とし、1しか提供できないHarnessはText生成を継続したまま route-unavailableでSpeechだけを停止する。HTTP 429またはadvertise値を超える応答は そのsessionをrender-failedにし、直列合成へ暗黙fallbackしない。

route解決に失敗した場合もsession IDを一つ発行し、preparingの直後に failed(code = "route-unavailable")をpublishしてruntime_runsをfailedへ確定する。 TurnEventHub.speechはNoneにしてText turnを続行する。session作成後のSettings変更はactive sessionへ反映せず、次sessionから使う。

AppSnapshot.speechPipelineModeを"streaming" | "final-only"として追加し、 StreamingSpeechRuntime.enabledから起動時snapshotへ投影する。Frontendは環境変数を直接読まない。 Compatibility phaseでfinal-onlyなら既存のmessageCompleted gateを使い、raw final textを 旧speak_textへ渡す。projectionは旧経路でもBackendの voice_text::text_for_speechだけが行う。 

const wantsSpeech = voiceSettings.autoSpeak && !meetingBlocksTts;
const speechReady = speechPipelineMode === "final-only" || speechSubscriberStatus === "ready";
const presentationMode = wantsSpeech && speechReady ? "visual-and-spoken" : "visual";

modeがstreamingなのにsubscriberが未接続または接続失敗なら、Text turnは visualで継続し、既存の非blocking error領域へ「読み上げ接続を開始できなかった」を一度表示する。 この場合だけ旧final-onlyへ暗黙fallbackしてはならない。

start_turnは新turnを実行する前に旧Speech SessionへNewTurn cancelを要求し、 Section 7.5のterminal cleanupを待ってから新Speech Sessionを作る。旧Speechの停止失敗または新Speechの route作成失敗をstart_turnのErrへ伝播せず、SpeechEventへ閉じ込めてText turnは開始する。

8.3 Frontend subscription / reducer

  1. Chat shell mount時にUUIDのsubscriptionIdとChannel<SpeechEvent>を一度作り、 channel.onmessage = event => dispatchSpeechEvent(event)を同期handlerとして設定する。
  2. subscribe成功後だけcleanupでunsubscribeする。cleanupは同じIDを渡し、active sessionがあれば stopを送る。Channel callback内でawaitしない。
  3. local statusはconnecting | ready | failedとする。mount直後はconnecting、subscribe command成功でready、 command失敗でfailedにする。自動reconnect loopは本変更へ含めない。
  4. reducerはsessionId + generationをactive keyにし、古いkeyのeventを無視する。 preparingだけがactive keyを新規作成できる。
  5. readyToPlayを受けたeffectがsuspendVoiceForSpeechをawaitし、成功時だけ ack_speech_readyを呼ぶ。同じkeyへのackはSetで一回にする。await完了時にactive keyが変わって いたらackせず、そのkeyについてcaptureが実際に停止済みなら直ちにresumeする。
  6. completed | cancelled | failedでterminal stateを確定し、そのkeyでsuspend成功を記録済みの場合だけcaptureを一度resumeする。 reducer自身はcommandを呼ばず、effect層がstate transitionを見て実行する。

8.5 Microphone coordination

現行のsuspendVoiceForSpeechとresumeVoiceAfterSpeechはsession単位へ変更する。 SpeechEvent::audioStartedより前にcapture停止を完了させる必要があるため、Backendは最初のaudioをrenderした時点で readyToPlayを送り、Frontend coordinatorのvoiceSuspended ackを待つ。readyToPlayのChannel送信成功直後からBackendの1秒timerを開始し、ackがなければ Playerへappendせずcapture-suspend-timeoutでfailedにする。

実装は「Frontend suspend → Backend ack → playback」の順を採用する。BackendだけでmacOS microphoneを 停止できると仮定しない。ack timeout初期値は1秒とし、自己音声loop防止を開始速度より優先する。

12. Rollout / Rollback

  4. Cleanup release: default-on releaseの実運用証跡がありrollback未使用だった場合だけ、 旧speak_text / stop_tts、final-only gate、flagを削除する。未確認なら削除ticketを延期する。

15.1 Measurement protocol

  1. src-tauri/testdata/streaming_tts_corpus.jsonを追加し、chunker fixtureと同じsynthetic raw answersを参照する。日本語20件（prose 10 / Markdown 5 / URL・数値・括弧5）、英語10件（prose 5 / Markdown 3 / URL・数値2）へ固定し、測定中に本文を差し替えない。
  2. corpus schemaは{ id, language, category, raw, deltaEndBytes, expectedSpokenChunks }とする。 deltaEndBytesは昇順のUTF-8境界で最後がraw.len()、IDは重複不可、expected列は Section 6.7の値と一致する。Rust testでschemaと全offsetをvalidateする。
  3. baselineと変更後は同じraw + deltaEndBytesを20ms間隔でfake ordered Turn Event Hubから送り、TTSだけ実providerを使う。network LLMの速度差をlatency比較へ混ぜない。Real LLM route smokeは別Gateとして成否だけ記録する。
  4. provider / voice / machine / macOS / build commitを固定し、各batch前のwarm-up 3回は集計から除外する。
  5. batch直前にappを再起動してmetric bufferを空にし、batch直後にdiagnosticsをexportする。異なるprovider、 cancel phase、corpus revisionを同じbatchへ混ぜない。
  6. p50 / p95は昇順配列のindex = max(ceil(p * n) - 1, 0)を使うnearest-rankとし、 averageや補間値で置き換えない。
  7. evidenceへsample数、raw値、算出値、Pass / Failを記録する。診断exportとevidenceに回答本文、credential、 endpoint、artifact pathを転記しない。

firstMin = 10は固定要件ではなく初期仮説である。自然さが3未満になる、TTS request数が 過大になる、またはgapが閾値を超える場合は、同じcorpusで10、16、24を比較し、最小の合格値を採用する。 値を変更する場合はevidenceへ比較値を記録してSection 6.1とfixtureを同じcommitで更新する。 Gateを満たせない場合はNo-Goであり、実装者がthreshold緩和、audio crate変更、全文一括合成への回帰を 独自判断してはならない。
