5. 重複除外後の実装チケット

R01 — smokeテストと終了待ちを安定化する（最優先・未着手）

対象：scripts/desktop-smoke-process.ts、tests/desktop-smoke.test.ts、tests/desktop-smoke-descendants.test.ts。300msや固定回数のsleepに成功判定を依存させず、fixtureの起動完了・signal受信・終了を明示的に同期する。まず今回停止したbuild段階のspawn／exit／closeを記録し、イベント取りこぼし、runner挙動、負荷のどこが原因かを確定する。原因をCPU負荷と決めつけない。

テストの全体期限は起動・終了の各期限を含める。timeoutが起きても親・子・marker・scratchを回収する。子のstdio継承あり／なし、SIGTERMを無視するケース、早期終了、spawn失敗を保持する。確認用ログに秘密・個人パスを残さない。

完了条件：対象2ファイルを通常20回と制御した負荷下20回実行して失敗0、各失敗fixtureは期待したエラー種別を返し、終了後のprocess／一時データ残留0。反復成功だけを決定性の証明とせず、成功判定がイベント・状態に基づくことをレビューする。timeout延長だけでは完了にしない。

R02 — oxlint／oxfmtと整形後サイズ管理（未着手）

依存はBunでdevDependenciesへ追加し、採用時のバージョンを固定してbun.lockへ保存する。.oxlintrc.json、.oxfmtrc.jsonとlint、format、format:checkのローカルscriptを用意する。対象は自分たちが管理するsrc、tests、scriptsのTS／TSXとvite設定。generated bindings、vendor、dist、node_modules、target、HTML仕様は除外し、HTMLは既存spec-htmlを使う。

公式仕様に基づき、oxfmtは--checkで非変更検査、書込はformatコマンドに分離する。oxlintはreact pluginを明示し、react/rules-of-hooksとreact/exhaustive-depsを最小必須規則にする。型検証は既存tscを維持する。採用版のCLIで規則の存在と設定を確認し、experimentalなReact Compiler規則を自動的に全部有効化しない。exhaustive-depsの危険な自動修正は使わない。

整形前後のAST上の変更と行数増加を分けて記録する。最初に隔離コピーでoxfmtを適用して超過箇所を列挙し、App／Chat／Situation／Meetingを責務単位に分割する。整形で増えたファイルのratchetは、formatter以外の変更がない前後対応表をレビューした場合だけ移行する。無関係の基準は維持し、hard上限を黙って上げない。formatter設定・size script・baseline・分割を整合した単位で反映する。

完了条件：適用範囲でlint／format:check／tsc／size:checkが成功し、2回目のformatに差分がない。未登録0、意味変更は対応テストを持つ。新規ローカル統合script check:localをformat:check → lint → checkの順で用意する。既存CIが呼ぶcheckへの新規lint接続とworkflow変更は今回行わない。noUncheckedIndexedAccessは影響評価を別途行う候補であり、本チケットの必須条件にしない。

R14 — 巨大関数とProvider重複の限定分割（条件付き・未着手）
