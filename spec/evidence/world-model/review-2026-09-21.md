# WorldModel 再レビューと修正記録

対象: 五要素World、M2A Frame、M3B送信、M4A受入、G1会話接続。2026-09-21。
共有作業ツリーで他の改修・commitが進行しているため、HEADだけでは今回の変更範囲を表さない。
この記録は実装の無欠陥や全Providerの実モデル受入を保証するものではない。

## 修正した問題

| 重要度 | 問題と再現条件 | 修正 |
| --- | --- | --- |
| P1 | 期限内に始めた再検証が元Frameの期限後に終わってもCurrentになり得る | 再構築終了後も元のcaptured/expiresを検査。TTLは更新しない |
| P1 | 本文にWorldブロックがなくても有効なhandleだけで送信済みにできる | OpenAI互換とAgentSessionの履歴処理で実ブロックの存在も条件にする |
| P1 | AgentSessionのwrapper構築中に期限を越えたFrameを初回送信できる | 初回request構築境界で再検証し、失効なら非World本文へ差し替える |
| P1 | reasoning MCPの履歴とevidenceにWorldを重複掲載し、evidence枠から落ちた候補もselectedとして記録する | Worldはevidenceに一回だけ。枠に採用された本文と記録を照合し、構築後も再検証する |
| P2 | グラフをbyte上限まで採用した後、省略理由の追加で全体がBudgetTooSmallになる | 後続unitがある間は省略理由の容量を確保し、既存の説明単位を壊さずに縮小する |
| P2 | 五要素fixtureがGoal有効化前の時計を使い、Goalなしで合格していた | 最後のcommit以降を観測時刻にし、実HTTPのGoal・相関・依存をassertする |
| P2 | M4A runner不在でG1のHTTP/性能受入が保留されたまま | `world:eval`、loopback HTTP fixture、report、実時計の性能試験を実装 |

回帰試験は旧条件で失敗する期限跨ぎ・本文欠落・byte境界を含む。fixtureは合成DBのみで、外部Providerの資格情報を使わない。

## Blockerの原因と扱い

1. M4Aを実装済みとする前提に対し、runnerとHTTP受入の成果物がなかった。M4Aを独立したコマンドとして補完した。
2. M4A/G1はAgentSessionを対象外としていたが、後続WDが初回のみWorldを送る仕様へ変更していた。WDの契約を正本とし、旧計画の該当条件を更新した。TTL延長で回避していない。
3. 共有作業ツリーにはWorld以外のformat/size等の失敗がある。閾値を引き上げて全体合格にしない。

## 検証と限界

詳しいコマンドと結果は `m4a-results.md`、機械可読の結果は `m4a-report.json`。
OpenAI互換は受信raw bodyのSHA-256とgenerationを照合。AgentSessionは受信JSONをdecodeし、初回/継続のWorld有無とrequest digestを照合。MCPはtools/callのargumentsとselectedを照合する。

W12は両実adapterのHTTP失敗→切替と共通fallback可否判定を通す。設定解決を含むルート全体のE2Eとは区別する。
W18は独立した合成DBを同時実行し、異なるowner revisionの混入を検査する。同一DBの複数run競合は既存generation/scope試験の範囲。

WD全体の完了とは区別する。`world-delivery/route-matrix.md`にあるCodex receipt、reasoningの独立したversioned World契約、全経路の実モデル・UI・音声受入は、このoffline受入だけでは完了と判定できない。Situation/DW/scheduleの共通Frameへの統合も、metadata snapshotやStateAnswerの存在だけで実装済みとしない。
